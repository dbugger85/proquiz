# ProQuiz

A Jeopardy-style team quiz. The host laptop runs a small server, a TV shows the game, and each team's phone is a buzzer on the same Wi-Fi. A second kind of quiz, the **Quick quiz** (multiple choice in sections, every phone a player), runs on the same server and screens. `PLAN.md` has the user's decisions and the build steps, so read it first.

- **Repo:** `dbugger85/proquiz` (public, branch `main`). Commit and push only when the user asks.
- **Owner:** a beginner "vibe coder". Explain changes in plain language and keep user-facing text free of jargon. Everything the user sees must exist in English and Norwegian.

## Commands

```sh
npm install      # once (installs `ws`)
npm start        # starts the server, prints the host, TV and phone addresses (port 3000, or the next free one), opens the host page (PROQUIZ_NO_OPEN=1 to skip)
npm test         # unit tests + server tests (node --test)
npm run e2e      # browser tests (e2e.mjs, e2e-crazy.mjs, e2e-single.mjs, e2e-quick.mjs, e2e-remote.mjs, e2e-brand.mjs): host, TV and 3 phones (4 in e2e-quick) in headless Chromium (/usr/bin/chromium); screenshots in test/screenshots/
npm run build    # dist/ProQuiz-<version>-<system>.zip for Windows, Mac (arm64 + Intel), Linux (x64 + arm64), via deno compile
gh release create v<version> dist/*.zip   # publish (only when the user asks)
```

Run `npm test` and `npm run e2e` after any change, and look at the screenshots after UI changes.

## Stack and rules

- **Server:** `server.js` uses only `node:*` modules plus `ws`, because it must also run inside `deno compile`. Find files through `new URL(..., import.meta.url)` and never through `process.cwd()`. It starts only when `import.meta.main` is true, so tests can import it.
- **Browser:** plain HTML, CSS and JavaScript ES modules. No framework and no bundler.
- **Game rules:** `lib/game.js` is a pure reducer: `apply(state, action)` returns a new state. It has no DOM, no sockets and no `Date.now()`: actions that need the time carry `now`, and timers are stored as `state.deadline`. The server sends `{type:'timeout', now}` when a deadline passes. Actions that don't fit the current phase return the same state object, and bad joins, wagers or settings throw `GameError` with a `code`. Add a test in `test/game.test.js` for any rule change.
- **Who sees what:** `hostView` shows everything, `displayView` (the TV) hides answers until they're revealed, and `phoneView` never contains questions or answers. Tests check this, so keep them passing. **The one exception:** in a Quick quiz with the lobby setting `quickPhoneText` on (on by default, so nobody has to look at the TV), `quickPhoneView` adds the question text (from `ready`) and the option texts (from `open`); the right answer still only comes at `result`, and file names never.
- **Sounds and flashes:** these are driven by `state.event` (`{seq, type, ...}`). Clients react when `seq` changes. Sounds are synthesized in `public/js/sounds.js` (no files), and each team's buzz is a note chosen by its colour index. **The TV plays the sounds.** The host laptop plays them only when no TV screen is connected (`displays === 0` in the state message). Both show a "click to turn on sound" pill until the browser allows audio. The `sound` setting (key M) turns them off. The last 3 seconds of any timer tick.
- **Background music** (`public/js/music.js`): nothing is stored in the game. `moodFor(view, now)` derives the mood from the phase (lobby, board, thinking and hot in the last 3 s of the buzz timer, answering, `calm` at `revealed` and the Quick `result`, `calmUp` at the Quick `ranks`, final/finalQ/judge, over; silent in `special` and whenever the question has a sound clip; `off` when `settings.music` is false). `MOODS` (exported) maps each mood to a built-in song (`SONGS`: day, tick, slow, party, and the ambient `glow` (no drums, 72 bpm) for calm/calmUp, 16-step patterns played by a lookahead scheduler on the shared AudioContext, with its own gain into the shared limiter from `audioGraph()` in sounds.js) with a set of layers and a level, or to the host's own file (`settings.musicFiles[mood]`, one of `MUSIC_MOODS`, uploaded via `/api/files` from the lobby). The same song only ramps its layers; a different song or file crossfades; a mood's `delay` holds a new song back (`calm` waits 1.2 s so the reveal chime stands alone, `over` waits for the fanfare). Optional song keys tune `playStep()` (`longBass`, `bassSteps`, `padAttack`, `padFilter`, `padSteps`, `bellEvery`, `arpType`, `arpGain`, `arpOctave`); left out, they give the old sound, so the first four songs sound as before. Files that fail to load fall back to the built-in song. It plays where the effects play (the TV, or the host when `displays === 0`), and `syncMusic` runs on every update plus every 250 ms. `body[data-music]` shows the mood for tests. Settings: `music`, `musicVolume` (0–100, default 35), `musicFiles`; the B key toggles music. The TV reuses the slowly-appearing-picture canvas between updates (no flash).
- **Single-screen mode** (no separate TV screen, `tvs === 0` in the state message): once the game starts, the host page shows the TV view in an iframe (`/display?embedded`, which says `embedded: true` in its hello and isn't counted in `tvs`) with the controls underneath. The embedded TV makes board tiles clickable and passes key presses and tile clicks to the host page with `postMessage` (`handleKey()` in host.js). The freeze choice and final judging get team buttons in the controls bar. H (`peek`) switches to the normal host view with a warning note; F is full screen. The iframe is kept between updates (moving it would reload it) and removed as soon as a real TV screen connects. Sounds and music play in the iframe (`displays` counts it), and it unlocks audio itself.
- **Picking on the phone** (setting `phonePick`, on by default): `phoneView` gives the picking team `canPick` and `board` (category names, values and `used` only, never questions, answers, files or specials) while the phase is `board`. The phone sends `pick {c, i}`, and the server adds its `teamId`. `pick` in game.js refuses non-integer tiles and, when a `teamId` is given, anyone but `state.picker` or the setting being off. Host clicks (no `teamId`) always work. The phone shows categories first, then their points (`pickStage()`, `pickCat`). The host's board hint and the TV say the team picks on its phone when that phone is connected.
- **Fair buzzing** (setting `fairBuzz`, off by default): every phone answers the server's `clock {id}` with `clock {id, t: performance.now()}` (net.js does this before `onMessage`) and sends `buzz {at}` with its press time (the touch event's `timeStamp`). The server (`ping()`, `clockSample()`, `bestSample()`, `pressTime()` in `createHub`) measures each phone 5 times on hello or `resync` (sent when the page becomes visible), once every 5 s and once on `arm`, keeps samples for 20 s, and uses the one with the shortest round trip: `offset = t − (sent + rtt/2)`. A buzz gets `at` (server time) and `slack` (rtt + 5, at most `MAX_SLACK_MS` 250, or `MAX_REMOTE_SLACK_MS` 600 for a phone over the internet: `slackCap(c)`) from the server only, never from the phone; game.js caps it at the larger one. In game.js the press counts as `min(now, max(now − slack, at, q.armedAt))`, a press more than `slack` before `q.armedAt` is `early`, and the first arrival sets `q.decideAt = now + wait` instead of winning, where `wait` (from the server's `buzzWait()`: the largest rtt + 5 of the other measured phones) is clamped to `BUZZ_WINDOW_MS` (150) … `MAX_REMOTE_SLACK_MS`, so a slow phone elsewhere still gets its earlier press counted; `timeout` at `decideAt` runs `decideBuzz()` (earliest press wins, `buzzes` sorted). If every team that may buzz has buzzed it decides at once. `nextTimerAt(state)` is what the server schedules (the window, else `deadline`). Unmeasured phones count by arrival. The host gets `latency {teamId: ms}` in state messages and `latency` messages (shown in the lobby team list). `test/fairbuzz.test.js` uses pretend phones with wrong clocks and lag.
- **Round 2** (`set.round2 = {categories}`, setting `round2`, on by default, lobby tick `#round2-setting` shown only when the quiz has one): `state.round` is 1 or 2, and `boardOf(s)` (crazy.js, re-exported by game.js) is the board being played; everything that reads the board goes through it. `hostView`/`displayView` put the current board in `set.categories` (the host also keeps `set.round2`), so the screens don't care which round it is, and views carry `round`. `endBoard()` in round 1 with a round 2 runs `startRound2()`: `round = 2`, fresh `used`, `picker = lastPlace()`, specials re-placed (`placeAllSpecials()`), pot kept, phase `round2` (the intro; event `round2`, phone status `round2`, music mood `board`), and `next` goes to `board`. Validation problems on round 2 have `r: 2`; the editor's `boardParts(r)` draws either board and `openQuestion(c, i, r)` edits it; AI-filled marks use `2:c-i`. `gapsOf()` gives round 2 tiles `r: 2` and `names2`; `buildRequest({round2, round2Topics})` and `parseReply(…, {round2})` handle making one.
- **Main menu** (`#menu-btn` in the host bar, shown outside the lobby; host message `mainMenu`, `mainMenu()` in `createHub`): works like closing and restarting ProQuiz. The game becomes `resumable` (in memory; not saved right away, so the file keeps the game), `state` is a `newGame` with the same quiz and settings and no teams, and every phone gets `welcome {teamId: null}` with `askedTeamId` kept. `resume()` merges teams that joined in the lobby meanwhile: same id = the saved team (score kept); new ones (not a saved id or name) are added with score 0 and a free colour if theirs is taken (and `final.base` 0). `start` drops `resumable`. The end screen's "Back to the main menu" is different: it's `restart` (same teams, scores to zero).
- **Undo** goes back exactly one step: every host step calls `remember()` (pick, arm, correct, wrong, reveal, timeout, next, end, freeze, setPicker, judgeFinal, adjust).
- **Autosave:** the server writes `autosave.json` to `PROQUIZ_DATA` (default `~/ProQuiz/`) about 250 ms after each change. On start, a saved game with teams is offered in the host lobby (`msg.resume`). The host sends `resume` or `discardSave`, and a new game keeps the saved settings. On resume, phones that already said hello with their team id get a fresh `welcome` with it. Tests always pass a temporary `dataDir`.
- **Pictures and sound clips:** a question (or the final) can have `image` (shown with the question), `answerImage` (shown only when revealed, and never sent to the TV before), and `audio` with an optional `audioStart` in seconds. They are plain file names (`IMAGE_NAME`/`AUDIO_NAME` in `lib/validate.js`) served at `/files/<name>` (with Range support), from `<data dir>/files/` first and then the bundled `sets/files/`. Uploads are named after their content (sha256, 16 hex characters). The TV loads pictures and clips early while the board shows. Phones never get file names.
- **Slowly appearing pictures ("unveil"):** a question with `image` can have `unveil` (seconds, 1–120, validated, and `clean()` keeps it only with a picture). `openQuestion()` sets `q.unveil = {ms, done, since}`, and `syncUnveil()` (run in `apply()` after `syncMedia`) makes it run while `armed` (and during a solo answer), pause otherwise, and be complete at `revealed`. `openBuzzers()` adds the remaining unveil time to the buzz deadline. The TV draws a `canvas.unveil` through the block steps `STEPS` in display.js (a small canvas scaled up without smoothing) on the server clock, and only puts the clear `<img>` on screen once the answer is revealed. The host shows "Picture: n% clear". Resume moves `since` to now. The word "unveil" is used so it isn't confused with `reveal` (show the answer). Not on the final question.
- **Clip playback:** `state.media` (`{playing, seq}`) is set by `syncMedia()` in `lib/game.js` after every action. A new question starts its clip. A buzz or the final's judging pauses it, and the re-opened buzzers and the reveal play it on. `mediaToggle` (P) and `mediaRestart` (0, which bumps `seq`) are host actions. `public/js/clip.js` makes an `<audio>` follow that state. It runs on the TV, or on the host when no TV is open. Views carry `clip: {file, start}`.
- **Quizzes and the editor:** `store.js` keeps quizzes in `<data dir>/sets/<id>.json` (the built-in `sets/sample.json` is id `sample` and read-only) and runs the editor's HTTP API under `/api/` (loopback only): list/get/create/save/delete sets, `POST /api/files?name=` for uploads (25 MB max, image or audio only), `GET /api/export/:id` (a `.proquiz.json` with the files inside as base64) and `POST /api/import`. Saving is allowed with problems (drafts), but only valid quizzes can be chosen in the lobby (`chooseSet` host message). Saving the quiz that's on show in the lobby reloads it there. A new game keeps the last quiz and settings from the autosave. `state.setId` tracks which quiz is loaded.
- **Quick quiz** (`set.kind === 'quick'`, `modeOf(set)` in validate.js; rules and views in `lib/quick.js`). **Mode dispatch:** `newGame()` sets `state.mode` from the set (`loadSet` too), and `apply()` picks the handler with `handlerFor()` in game.js: in quick mode `quickHandlers` first, then the board handlers listed in `SHARED` (join, settings, loadSet, adjust, undo, restart, mediaToggle, mediaRestart); board-only actions do nothing in a quick game and `answer`/`skip` nothing on a board. `hostView`/`displayView`/`phoneView` hand off to `quickHostView`/`quickDisplayView`/`quickPhoneView` on their first line, so the server doesn't care which mode it is. game.js and quick.js import each other (only used inside functions). Phases: `lobby → section → ready → open → result → ranks → (ready | section | over)`; Space is `next`, Esc is `skip`; `ready` ends by itself after `quickReadSeconds` (0 = wait for Space), `open` after the question's seconds or as soon as every player has answered. Each phone is a player (up to `MAX_PLAYERS` 30, colours may repeat, `full-players`; a board quiz refuses more than 8 with `too-many-teams`). `answer {option, at}` from a phone gets `at`/`slack`/`lead` from `pressTime()` like a buzz, and `fairOn()` in server.js is `fairBuzz || mode === 'quick'`. `lead` is half the measured round trip (capped at `MAX_REMOTE_SLACK_MS / 2`): `pressTime` already corrects the way back (press → server) through the clock offset, but not the way out (the answers reaching the phone), so `answer` stores `max(openedAt, pressed − lead)` and a far-away player isn't scored lower. A press after `deadline` is refused, and the server's timer for `open` waits `answerGrace()` longer (half the slowest remote phone's rtt + 20 ms) so such answers still arrive. Points: `pointsFor()` (1000 at once down to 500 at the last moment, ×2 or 0 by `points`, plus the optional streak bonus `quickStreak`). **Several right answers:** a question may mark more than one option right; a player still picks one, and any right one scores (`isRight(q, option)` in quick.js, through `rightSet()`). `state.q.correct` and every view's `q.correct` (host always, TV and phones from `result` on) are a sorted **list** of indices, even for one right answer; the screens mark every right option (TV tiles and bars, host ✓, the phone's "Right answers:" chips) and count everyone who picked any of them. Views carry standings entries `{id, name, color, score, rank, delta, move, places, streak}` (and at `ranks`, `ranks.before` from `standingsBefore()`: the top 5 as it stood when the answers opened, `{id, name, color, score, rank}`, without late joiners), `q.fastest` from `result`, and the phone's `behind`/`ahead` (the gap line). Settings `quickReadSeconds` (4), `quickStreak` (off), `quickPhoneText` (on) live in the lobby's `#group-quick`, shown only in quick mode (Crazy, rules, round 2, final and own specials are hidden). `resumeFix()` restarts a showing question on resume. Screens: `body[data-mode]` on all three pages; the TV's quick screens, the phone's shape buttons (`shapeSvg()`, `optionStyle()` in ui.js; `SHAPES` and `OPTION_COLORS` in quick.js), and the host's question view and sorted player list. Sounds and music moods follow the quick phases (`music.test.js`).
- **Quick quiz file format** (checked by `checkQuick()` in validate.js, cleaned by `cleanQuick()` in store.js): `{v: 1, kind: 'quick', title, sections: [{name, seconds?, questions: [{question, options: [2–4 texts], correct, seconds?, points?, image?, audio?, audioStart?}]}]}`. `correct` is the index of the right option, or a list of indices when several are right (any of them counts); `rightSet(q)` in validate.js reads both as a sorted list, so old files keep working. `clean()` saves one right answer as a number and several as a list, and left out until one is marked. At least one, all in range, no repeats (`bad-correct`), and not every option (`all-correct`); `seconds` 5–120 falls back to the section's, then 20; `points` is 1000 (left out), 2000 or 0. Limits: 10 sections, 30 questions each, options 80 letters. Problems use `c` for the section and `i` for the question (codes `no-sections`, `no-section-name`, `bad-options`, `bad-correct`, `bad-seconds`, `bad-points`, …). `clean()` drops empty options except the ones marked right (the marks follow their options). The samples are `quick-sample` (English) and `lynquiz` (Norwegian); each has one question with two right answers.
- **Making a quiz with AI** (`lib/aiquiz.js`, shared by the editor and `test/aiquiz.test.js`): copy and paste only, ProQuiz never calls an AI. `buildRequest(opts)` writes the request (always in English, with one line saying which language to write the quiz in, plus a format example in that language), and `parseReply(text, {final, title})` reads the pasted answer. It takes the ``` block (or the text from the first `{` to the last `}`), tries `JSON.parse`, then `repairJson()` (curly quotes around keys and values, trailing commas, `//` comments), keeps only value/question/answer (cut to the editor's lengths; a missing or text `value` becomes a number), and returns `{set, problems, duplicates}`, or throws `AiQuizError` with a code from `AI_ERRORS` (translated as `ai-<code>`). The editor's **Make questions with AI** dialog (`openAiDialog()`) always makes a new quiz and shows a "check every answer" note (`aiNote`, not saved) until another quiz is opened. Its **Kind of quiz** select (`aiOpts.kind`) switches to a Quick quiz: `buildRequest({kind: 'quick', sections, perSection, topics, difficulty, lang})` (`buildQuickRequest()`) asks for sections whose questions have 4 options (or 2 for true or false) and an `"answer"` copied from the options (a list of them for the occasional question with 2–3 right options; the format example has one), and `parseReply()` reads a reply with `sections` (or any reply when `kind: 'quick'` and both are there) into a quick set, taking the right options by text, index or letter A–D, or a list of those, from `answer`/`answers`/`correct`/`right` (`rightOptions()`; one found = a number, several = a list, none = no `correct`, so the editor asks for it). Filling empty spots is board-only (the button isn't shown for a quick quiz).
- **Filling only the empty spots with AI** (same file): `gapsOf(set)` lists tiles needing `both`/`answer`/`question`, nameless categories, the final's missing fields, and `skipped` picture/clip questions without text (the AI can't see them). `guessLanguage(set)` guesses en/no from the text. `buildFillRequest(set, {difficulty: 'match' | level, topics, lang})` shows the quiz so far as JSON (`""` = missing, `[picture]`/`[sound clip]` and `[keep]` for what it must leave, never specials) and says what to fill and how to match. `parseFill(text, set)` merges only the gaps (named categories matched by name, the rest take leftover categories, questions by position or points), never changes anything else, and returns `{set, filled, names, final, left, duplicates}` or throws `nothing-filled`. The editor's **Fill empty spots with AI** button (`openFillDialog()`) marks filled tiles with `.ai-filled` until another quiz is opened.
- **Editor page** (`/editor`, `public/js/editor.js`): the quiz list, the board as tiles, and a `<dialog>` per question with the picture and clip pickers. A Quick quiz (`quick()`, made with **New quick quiz** / `blankQuickSet()`) shows section cards instead (`renderSections()`: name, seconds per question, the questions as rows with ▲ ▼ ×, Add a question, Add a section); `catsOf()` returns the sections, so the problem marks and texts work the same, and `openQuestion()` uses `quickFields()` (question, 4 answer slots in their colours and shapes with a **Right** checkbox each (several may be ticked), seconds, points select, picture and clip). Empty answers are saved out, so the ones after a gap move up in the game: the dialog says so while there is a gap (`edOptionsGap`) and moves them up itself when focus leaves the answers block (`moveUp()`, `edOptionsMoved`; not on each field's blur, which would move text under a click on **Right**), the right marks moving with their answers. The question rows show a chip per right answer. It autosaves 600 ms after each change. Completely empty questions and categories aren't marked red, just counted. Use `fill()` from ui.js instead of `replaceChildren()` when a child might be null.
- **Final round:** the TV shows the category and bet ticks, then the question with answer ticks, then judge cards that fill in as the host marks each team. The right answer appears when every team is judged. The host's final screen has Correct/Wrong per team (click again to clear). On phones, `stageKeyFor()` means the stage is only rebuilt when something that team sees changes, so typing a bet or answer isn't wiped out by other teams' updates. Teams with no points to bet send 0 automatically.
- **Kaosmodus / Crazy mode** (`lib/crazy.js`, setting `crazy`: off/some/lots, plus `crazyExclude`: the kinds the host unticked in the lobby): at `start` the server rolls a `seed`, and `placeSpecials()` fills `state.specials` (`{"c-i": kind}`, about 1 in 8 or 1 in 4 tiles, a triple and a bomb first unless excluded, at most one turbo, jackpot, rescue and double, and fewer if too few kinds are left; each goes in the category with the fewest specials so far, and the one-team kinds in `SOLO` (hotseat, rescue, turbo, double) never go on a question with a picture, nor does turbo pull one into its queue). Picking a special tile goes to phase `special` (the TV reveal, `event: special`). `next` runs `startSpecial()`: triple ×3 (`q.baseValue`), bomb (instant loss of the value, result `boom`, no question), hotseat/rescue/turbo set `q.solo` (only that team answers: `arm` goes straight to `answering`, no buzzing, no reopen, and rescue and turbo have no penalty), jackpot adds `state.pot` (all points lost while specials exist) on a right answer, freeze puts `q.frozen` (chosen on the picking phone with `freezePick {target}`, status `freezeChoose`, or with the host action `freeze`) in `lockedOut`, and double (Daily Double) takes `q.bet` during `special` (`bet {amount}` from the picking phone, status `bet`, `view.betting = {bet, max, value}`, or from the host; 0 to `maxBet()` = the score or the board's top value), then sets `q.value` to the bet (the tile's value if none), `q.solo` and `q.fullPenalty` (a wrong answer costs the whole bet whatever `penalty` says).
- **Specials placed by hand:** a question can have `special` (one of `KINDS`, validated as `bad-special`, kept by `clean()` in store.js, never on the final). `ownSpecials(set)` collects them; at `start` they play when the setting `quizSpecials` is on (default, lobby tick shown only when the quiz has some), even with Kaosmodus off, and `placeSpecials(s, level, exclude, own)` adds random ones on other tiles, counting the own ones towards the number. `displayView` rebuilds the questions without them. The editor's question dialog has a **Special tile** select and the tile shows the icon. Turbo keeps `state.turbo` (`{team, queue, n, total}`, 3 questions, 5 s each), and `next` after a reveal opens the next queued tile by itself. **Secrets:** `displayView` deletes `specials`, `rng` and `pot`, and `phoneView` only gets `special`/`solo`/`frozen` of the open question. Tests place specials with `start {specials}` (the server strips that from host commands) or `hub.dispatch`. Icons and rule texts are in `public/js/specials.js`.
- **Lobby settings panel** (`#settings` in host.html): a Quiz block (picker, language, round 2, final + its seconds, own specials; always open), then native `<details class="settings-group">` sections: `#group-crazy` (open by default), `#group-rules`, `#group-sound` with the nested `#music-files` last in it, and `#group-look` (**Look and branding**: the glass tick, then the branding, see Branding), and `#group-remote` (**How players join**: the `joinMode` pills, then, over the internet, the status, **Try again**, the download, and the `#remote-pin-on` tick without a `name`). A Quick quiz shows `#group-quick` (status `#quick-status`) and hides the board-only parts. Order and defaults are the owner's choice (2026-10-10). Each `<summary>` has a status line filled by `renderSummaries()`. Language, penalty and Crazy level are radio pills (`.pills`): `renderSettings()` sets them through the form's RadioNodeList, and tests click `label:has(> input[name=…][value=…])` (`pickPill()` in e2e.mjs). Things that don't apply are hidden with the `hidden` attribute, not greyed out (final row without `set.final`, final seconds, below zero when the penalty is none, volume when music is off). Tests must open a closed section (click its `summary`) before touching what's inside.
- **Avatars** (a Quick quiz player's face, a board team's **mascot**; same data and builder): `lib/avatar.js` has the parts (`AVATAR_PARTS`: skin 6, hair 8 (0 = bald), hairColor 6, eyes 5, mouth 5, glasses 4 and hat 6 (0 = none)), `isValidAvatar()`, `cleanAvatar()`, `randomAvatar()` (glasses and hat off about half the time), `avatarKey()` and `avatarOf(team)` (`{avatar}` or `{}`, spread into views so teams without one look exactly as before). `join {…, avatar}` is optional; a bad one throws `bad-avatar`; joining again without one keeps it. It is part of the team object, so autosave, undo, restart, resume and the resume list (`summary()`) carry it, and every view and standings entry (`standings`, `standingsBefore`, `fastestOf`, `neighbours`, `you`, `teams`) has it. `public/js/avatar.js` draws it: `avatarSvg(a)` is SVG text (flat fills only: no filters, blurs or gradients; layers: shoulders, hair back, ears, head, cheeks, eyes, mouth, hair front, glasses, hat; a cap or beanie hides what would stick through it, and a bun or mohawk makes room for a crown or party hat), `avatarEl(a, cls)` a cached `<span class="avatar">` (or null). The tables (`SKINS`, `HAIRS`, `HAIR_COLORS`, `EYES`, `MOUTHS`, `GLASSES`, `HATS`) must have exactly `AVATAR_PARTS` entries (`DRAWN`, checked by `test/avatar.test.js`). The coin's background is CSS (`.avatar`: the team colour, or a darker circle on a plate; glass adds a shine), 1em by default, sized per place in the "avatars" block of style.css. **Phone:** `#avatar-field` on the join form (between the name and the colours): the preview in the chosen colour, the dice `#avatar-random`, `#avatar-edit` (Customise/Done) opening `#avatar-builder` with a tab per part and a tile per option (hair colours as dots); saved in `proquiz.team.avatar`, random on the first visit, always sent with `join`; the header `#me` shows it. **TV:** lobby plates (`.tv-lobby.crowd` over 12 players and `.packed` over 20 make everything smaller so 30 fit), the top 5 and standings (`rankFace()`: the face with `.rank-n` as a corner badge, so the top 5's FLIP still finds `.rank-n`), the podium (`.step-face`), the fastest plate, the score strip, buzzer and result plates, the final's teams and judge cards, the end list. **Host:** the lobby list, score rows, the Quick quiz side list, rank lists, the fastest plate and the resume list.
- **Team colours:** `COLORS` in lib/game.js (Apple-style colours for dark screens since 1.7; the index also picks the buzz note). `newColor()` turns a pre-1.7 colour (`OLD_COLORS`) into its new version: used by `join`, `resume()`/`summary()` in server.js and the phone's remembered colour. Keep `OLD_COLORS` so old saved games and phones still work.
- **Keep-awake:** `public/js/wake.js` uses Wake Lock where allowed, otherwise the tiny looping `public/media/keepawake.*` video, started on the first tap.
- **Host is laptop-only:** the server accepts `role: 'host'` only from loopback addresses (and never on the tunnel's listener, see below), because the host view contains the answers. The TV (`/display`) and phones can connect from anywhere. So the TV page can run on an iPad, another computer or a smart TV's browser (an Apple TV has none, so an iPhone/iPad/Mac mirrors it with AirPlay); the server prints that address and the lobby shows it (`tvElsewhereHint`).
- **How players join / players elsewhere** (`lib/tunnel.js`, lobby group `#group-remote`): the setting `joinMode` (`'wifi'`, the default, or `'internet'`; `JOIN_MODES` in game.js) is a pill choice like the other settings and is saved with them. **The server keeps the tunnel in line with it** (`syncTunnel()` in `createHub`): choosing internet starts the tunnel and choosing Wi-Fi stops it (checked in `dispatch()` whenever `joinMode` changes), and a host hello in the lobby starts it when the setting says internet and the tunnel is `off`. So a saved 'internet' never starts a tunnel when ProQuiz starts, only when the host page opens the lobby, and a failed one isn't retried by itself. `resume()` keeps the lobby's `joinMode` and `remotePin` (they belong to the session, not the saved game). The tunnel itself is a Cloudflare quick tunnel (`cloudflared tunnel --no-autoupdate --url http://127.0.0.1:<port>`, no account) gives a random `https://<words>.trycloudflare.com`. **Security:** cloudflared connects locally, so everything it passes on comes from 127.0.0.1; it is therefore pointed at a **second listener** (`openRemote()` in `startServer()`, 127.0.0.1 on a free port, opened when the tunnel starts and closed when it stops) where every connection is remote: `serveFile(…, {remote: true})` refuses `/api/`, `/host` and `/editor` (403), and `hub.connect(ws, req, {remote: true})` sets `c.remote` and `c.local = false` (no host hello). No headers are trusted. `createTunnel()` finds cloudflared (`candidates()`: PATH plus the usual install folders, next to the program, `<data dir>/bin/`), spawns it, reads the address with `parseTunnelUrl()` (ignores `api.trycloudflare.com`), and after "Registered tunnel connection" waits until the name resolves through DNS-over-HTTPS (`dnsReady()`, so no resolver caches "not found" from asking too early) and the address answers (`reachable()`), at most 30 s, before saying `on`. Status `{status: off|starting|on|missing|downloading|failed, url, reason: start|timeout|download|stopped, progress}`. `download()` fetches the official asset (`assetFor(platform, arch)`, `RELEASES` = GitHub latest download; Mac `.tgz` unpacked with `tar`) into `<data dir>/bin/` and starts. `stop()` is off at once (SIGTERM, SIGKILL after 3 s, since cloudflared waits for open connections); `process.on('exit'/signals)` kills it. Host messages `tunnel {on}` (sets `joinMode`; `on` while it already says internet tries again, the **Try again** buttons) and `tunnelDownload`. State messages carry `remote` (host: the status plus `remoteTeams`; TV: `{status, url}`, the url only when on) and, for a remote phone not in a team while a PIN is set, `needPin`. **PIN:** setting `remotePin` ('' or 4 digits, made by the host page's `newPin()`), checked in `checkPin()` for remote joins without a team (`bad-pin`; at most 10 wrong PINs a minute for all remote phones together, then `pin-wait`); never in `phoneView`, and blanked in the view of a TV page opened over the tunnel. Remote TV pages don't count in `displays`/`tvs` (so single-screen mode and the laptop's sounds stay) but still get `sound` messages. In a Quick quiz, the host page turns `quickPhoneText` on once per tunnel session when it is on (`remoteQuickDone`, with `#remote-note`). **Screens:** the host lobby and the TV show **one** QR code (`#qr`): the Wi-Fi address, or with `joinMode` internet the internet address (host: label `#join-label`, the PIN `#remote-pin`, the `/display` link `#remote-tv`; TV: `#qr-label`, the PIN `#remote-pin`). While the internet address isn't ready (starting, missing, failed) the host's join card shows `#join-wait` (status text, **Try again** / download) above a smaller Wi-Fi code labelled "On this Wi-Fi, for now" (`.join-card.waiting`), and the TV `#tv-wait` with the Wi-Fi code (`#qrs.waiting`). Long addresses wrap before a dot (`urlNodes()` in ui.js). During a game the host page shows `#remote-warn` (`renderRemoteWarn()`) when joining over the internet stopped, is starting again, or came back on a new address, with **Try again**. `startServer({tunnelOptions})` passes test doubles (`ready`). Tests: `test/remote.test.js` (listener refusals, PIN, pretend cloudflared shell scripts, download with a fake fetch) and `test/e2e-remote.mjs`.
- **Protocol:** client → `hello {role, teamId?}`. Phones then send `join {name, color, avatar?, teamId?, pin?}`, `buzz`, `pick {c, i}` (only the picking team), `freezePick {target}` and `bet {amount}` (Kaosmodus, only the picking team), `wager {amount}`, `finalAnswer {text}` and, in a Quick quiz, `answer {option, at}`. The host sends `cmd {action}` (allowed list: `HOST_ACTIONS` in server.js). The host can also send `resume`, `discardSave`, `mainMenu`, `testSound`, `chooseSet {id}`, `tunnel {on}` (same as choosing `joinMode`, or try again) and `tunnelDownload`. A phone's `buzz` in the lobby just plays its tone. The server → `welcome` (with `info.phoneUrl` and `info.tvUrl`, the TV page's Wi-Fi address shown in the host lobby, for host/display, `teamId` for phones), `joined {teamId}`, `error {code}`, `sound {name, teamId?}` (sounds outside the game, sent to the TV or else the host), and `state {view, connected, displays, tvs, serverNow, resume?, latency?, remote?, needPin?}` after every change. Error codes are translated as `err-<code>` in i18n.
- **Look:** a modern game-show stage: deep ink-violet, one soft stage light from above, glassy rounded tiles, pill buttons, and team colours as the loudest thing on screen. One dark theme on purpose (it is made for a TV). Colours are CSS variables in `:root` in `public/style.css`. Fonts are Unbounded (wide display face for headings and numbers) and Atkinson Hyperlegible (text), bundled in `public/fonts/` so the game works offline. Never load anything from the internet. Tap targets are at least 48px.
- **Glass look** (setting `glass`, on by default; lobby tick in `#group-look`, status `#look-status`): Apple-style frosted glass, all in the `body.glass` block at the end of style.css (`--lg-*` and `--glow-*` variables in `:root`). `setGlass()` in ui.js puts the class on `<body>` from `view.settings.glass` on the host, TV and phones (`phoneView` passes `glass`); the host also remembers it in localStorage (`proquiz.glass`) so the editor, which has no game state, follows it (`savedGlass()`). Real `backdrop-filter` only on big panels, bars and dialogs (`.tv-q`, `.settings`, `.host-side`, `.controls`, …) and the phone's buzzer/pick controls; the TV board tiles, buttons and pills fake it with gradients and a top highlight. The glow behind everything is two `::before`/`::after` layers moved with transform only (TV: tinted by the first teams' colours through `--glow-a/b/c`, set in display.js), and `prefers-reduced-motion` stops it. With the setting off nothing in that block applies, so the plain look stays as it was. The e2e takes `glass-on-*`/`glass-off-*` screenshots and prints the TV's frame times.
- **Branding** (`brand.js`, the host's own logo, event name and accent colour): the user's, not a quiz's and not a game setting. Stored in `<data dir>/brand/brand.json` (`{v, name, accent, plate, logo}`) plus at most one `logo-<sha256 16 hex>.<png|jpg|webp|svg>` there (old ones deleted); never in exports or the autosave. `createBrand(dataDir)` (loaded in `startServer()`) keeps it in memory: `view()` = `{name, accent, plate, logo: '/brand/<file>' | null}`, sent as `brand` in **every** state message (host, TV, phones, also over the tunnel). Changed only through `/api/brand` (so laptop only, 403 on the tunnel listener): `GET`, `PUT {name?, accent?, plate?}` (`cleanBrand()`: name ≤ 60 letters, accent `#rrggbb` or null = ProQuiz violet), `POST /api/brand/logo` (raw bytes, `MAX_LOGO` 2 MB → 413 `logo-too-big`, read to the end first; the type comes from the bytes, `logoKind()`, else 400 `logo-bad-type`), `DELETE /api/brand/logo` (writes refused with `Sec-Fetch-Site: cross-site`, so another website open in the laptop's browser can't change it); each calls `onBrand` → `hub.broadcast()`. `/brand/<file>` (only `LOGO_FILE` names) is served on both listeners with `logoHeaders()`: the real type, `nosniff`, a `default-src 'none'; …; sandbox` CSP and an immutable cache. **The logo is only ever shown with `<img>`** (`brandLogo()` in ui.js), never inlined, so an SVG's scripts can't run. **Screens:** `setBrand(brand)` in ui.js (host, TV, phone; the editor fetches `/api/brand`) sets the accent CSS variables on `<html>` (`accentVars()`: `--light-rgb`/`--flare-rgb` from the colour, the flare from `ACCENTS` or 40° round the wheel, the light darkened until white text has 3:1; and every tone in `TONES` (`--bg`, `--bg-deep`, `--ink`, `--muted`, `--panel`, `--pale`, `--primary-ink`, `--light-2/3-rgb`, `--deep-0…4-rgb`) re-hued to it; no accent removes them, so the default look is exactly as before), `body[data-accent]`, `body.has-logo`, the phone's theme colour, and puts the logo in every `.wordmark` (`.wordmark.logo`). So style.css must use these variables (`rgb(var(--light-rgb) / a)`), never the violet values. TV: the logo big with the name in `#tv-brand` above "Scan to join" and in `brandBlock()` on the end screen and the Quick podium; during the game small in the corner (`body.logo-corner` gives `.tv-stage` room), but not in the lobby, at `over` or in single-screen mode. Phone: the logo and `#brand-name` in the join form's `.join-head`. Host lobby: in `#group-look` (titled **Look and branding**), `#brand` with the preview, `#brand-file`, `#brand-remove`, `#brand-plate`, `#brand-name` (saved 500 ms after typing) and the `#brand-accents` swatches (`ACCENTS` plus `#brand-color`); nothing there sends `settings` (the form's change handler skips `#brand`). Tests: `test/brand.test.js`, `test/e2e-brand.mjs` (screenshots `brand-*.png`).
- **Pop-up questions:** never the browser's `confirm()`/`alert()`/`prompt()`. Use `ask({title, text, ok, cancel, danger})` → `Promise<boolean>`, `tell({title, text})` and `askNumber({title, text, value, preview, allowZero})` → `Promise<number|null>` from ui.js: a `<dialog class="pq-modal">` opened with `showModal()` (built fresh, removed on close; `danger` = red button and Cancel focused, otherwise the main button is focused, so Enter says yes; Esc = Cancel). Titles and button labels are the `dlg*` keys in i18n.js. While one is open (`modalOpen()`), the host page's keys (also those passed from the embedded TV) do nothing. The e2e tests answer them with `answerModal()` and fail if a browser dialog ever appears.
- **Top bar:** `.host-bar` (host and editor) is `position: sticky` (z-index 10: above the page, below the keyboard help and dialogs) and stays one row on a narrow window (the quiz title is hidden under 640px). The game screens' `calc(100vh - 73px)` heights assume its 73px.
- **Text:** all visible text goes through `t()` in `public/js/i18n.js` (both `en` and `no`), or `data-t` attributes in the HTML. `test/i18n.test.js` fails if a key is missing in either language.
- **Packaging:** the Linux build is tested here. Windows and Mac builds can't be run on this laptop, so ask the user to try them. The programs are unsigned: Windows shows SmartScreen ("More info → Run anyway"), and Mac needs right-click → Open. Both ask to allow network access.
- **Pages:** phones use `http://<LAN IP>:port`, which isn't a secure context. That means no Wake Lock, no service worker and no `crypto.randomUUID`, so use the fallbacks. (Phones joining over the internet tunnel use https, which is a secure context, but the code must work either way.)
