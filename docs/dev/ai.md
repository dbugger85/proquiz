# Making and filling quizzes with AI

Copy and paste only: ProQuiz never calls an AI. Everything is in `lib/aiquiz.js` (shared by the editor and `test/aiquiz.test.js`). "Translate with AI" is in languages.md.

## Making a quiz with AI

(`lib/aiquiz.js`, shared by the editor and `test/aiquiz.test.js`): copy and paste only, ProQuiz never calls an AI. `buildRequest(opts)` writes the request (always in English, with one line saying which language to write the quiz in, plus a format example in that language), and `parseReply(text, {final, title})` reads the pasted answer. It takes the ``` block (or the text from the first `{` to the last `}`), tries `JSON.parse`, then `repairJson()` (curly quotes around keys and values, trailing commas, `//` comments), keeps only value/question/answer (cut to the editor's lengths; a missing or text `value` becomes a number), and returns `{set, problems, duplicates}`, or throws `AiQuizError` with a code from `AI_ERRORS` (translated as `ai-<code>`). The editor's **Make questions with AI** dialog (`openAiDialog()`) always makes a new quiz and shows a "check every answer" note (`aiNote`, not saved) until another quiz is opened. Its **Kind of quiz** select (`aiOpts.kind`) switches to a Quick quiz: `buildRequest({kind: 'quick', sections, perSection, topics, difficulty, lang})` (`buildQuickRequest()`) asks for sections whose questions have 4 options (or 2 for true or false) and an `"answer"` copied from the options, and **a `"type"` on every question** (`quickRules()`, since the owner's first real AI quiz came back without any, 2026-10-11): `"choice"` (one right), `"multi"` (at most 1 in 5; answer = the list of every right option), `"order"` (at most 1 in 5; the direction in the question, options in the right order, no answer) or the rare `"any"` (at most 1 in 10; pick one, any of 2–3 right options counts, answer = the list), never saying in the question how many are right (the format example `EXAMPLE_QUICK` has a type on every question). `parseReply()` reads a reply with `sections` (or any reply when `kind: 'quick'` and both are there) into a quick set, taking the type from `type`/`kind`/`style` with common other names (`TYPE_NAMES`: choice/single/pick one, any/either (= an any-counts choice), tickall, checkbox, ranking, sort, …); **a missing or unknown type is guessed from the wording** (`guessType()`: sorting words → order (`looksLikeOrder()`: sort/order/rank/arrange/chronological, sorter/ranger/rekkefølge/kronologisk, and "oldest to newest" / "fra minst til størst" style pairs of superlatives; a plain "from west to east" is not one), a list answer of 2+ right options with plural wording → multi (`looksLikeMulti()`: "which of these are", "which … are/were", "select all", "all that apply", Norwegian "hvilke", "kryss av alle"), otherwise choice with a list staying any-counts). A type the reply gives is never changed. The right options come by text, index or letter A–D, or a list of those, from `answer`/`answers`/`correct`/`right` (`rightOptions()`; one found = a number, several = a list, always a list for multi, none = no `correct`, so the editor asks for it), and for order the options go in the order given by `answer`/`order` when it lists them all by text. `summarizeQuick(set, only?)` → `{questions, choice, multi, order, any, suspects: [{c, i, looks, question}]}` (`suspects` = pick-one questions whose wording sounds like multi/order) comes back as `summary` from `parseReply` (the whole quiz) and `parseQuickFill` (the touched questions only); the editor's `.ai-note` shows it through `aiSummaryLines()` (`aiReadSummary`/`aiNowSummary` with `aiKindChoice/Any/Multi/Order`, then an `.ai-suspect` line per flagged question, `aiLooksMulti`/`aiLooksOrder` with `edWhereQuick`). `duplicatesIn()` skips order questions. In the dialog the kind and size (categories/rows or sections/per section) come before the topics, and the topics hint says how many to write (`aiTopicsHint`/`aiTopicsHintQuick` with `{n}`, `aiTopicsHintQuickOne`).

## Filling only the empty spots with AI

(same file): `gapsOf(set)` lists tiles needing `both`/`answer`/`question`, nameless categories, the final's missing fields, and `skipped` picture/clip questions without text (the AI can't see them). `guessLanguage(set)` guesses en/no from the text. `buildFillRequest(set, {difficulty: 'match' | level, topics, lang})` shows the quiz so far as JSON (`""` = missing, `[picture]`/`[sound clip]` and `[keep]` for what it must leave, never specials) and says what to fill and how to match. `parseFill(text, set)` merges only the gaps (named categories matched by name, the rest take leftover categories, questions by position or points), never changes anything else, and returns `{set, filled, names, final, left, duplicates}` or throws `nothing-filled`. The editor's **Fill empty spots with AI** button (`openFillDialog()`) marks filled tiles with `.ai-filled` until another quiz is opened.

**Quick quizzes too:** `gapsOf`, `buildFillRequest` and `parseFill` dispatch on `set.kind` (the board parts are `boardGapsOf()` etc.). `quickGapsOf(set, {target})` lists `questions` `{c, i, need: ['question' | 'options' | 'correct', …]}` (fewer than 4 written options, unless `isTrueFalse(q)`: 2 options that are both yes/no words, or a question starting "True or false"/"Sant eller usant"; a "put in order" question is fine with 3; `correct` only when no written option is marked, never for order), nameless sections in `names`, `skipped` picture/clip questions without text, and `toAdd` `[{c, n}]`/`extra` for sections with fewer than `target` questions (`suggestedTarget(set)` = the most any section has, at least 5, at most 30; the dialog's `input[name=target]`, `aiFillUpTo`). The request (`buildQuickFillRequest`) shows the quiz as `{title, sections: [{name, questions: [{question, type, options, answer}]}]}` with `""` for gaps (every question with its type, `any` for a pick-one with several right options and `""` on a blank one; options padded to 4, or 2 for true or false), the right option(s) by text as `answer`, `[picture]`/`[sound clip]` + `[keep]` for what it can't see, the sections topped up with blank questions to the target, and the shared `quickRules()`. `parseQuickFill` matches sections by name, then by a question they share, then by place (`matchSections()`), questions by place; fills the text only when empty, reply options not already there into the empty places (an order question with missing options takes the reply's whole order, keeping its own words), `correct` through `rightOptions()` only when none was marked (refusing every option right on a pick-one), never the type; appends reply questions past the old length up to the target and 30 (stops at the first unusable one); returns `{set, filled (the added keys too), added, names, left, duplicates}`; the editor's `aiNote.added` shows `aiAddedNote`, and `questionRow()` marks `.ed-qrow.ai-filled`. Tests: `test/aiquiz.test.js` ("quick fill: …"), `test/e2e-quick.mjs` (screenshots `quick-editor-fill-dialog.png`, `quick-editor-filled.png`, and `quick-editor-ai-dialog.png` for the field order).
