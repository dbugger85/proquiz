# Editor, quizzes on disk and the export format

`store.js` (quizzes, files, archive, import/export and the `/api/` routes; the parts that don't touch the disk, `clean()`, the list summary, `slug()` and the export shaping, are in `lib/store-core.js`) and `public/js/editor.js`. The Quick quiz's own fields are in quick-quiz.md, the AI dialogs in ai.md, pictures and clips in media-and-pictures.md, languages in languages.md.

## Quizzes and the editor

`store.js` keeps quizzes in `<data dir>/sets/<id>.json` (the built-in `sets/sample.json` is id `sample` and read-only) and runs the editor's HTTP API under `/api/` (loopback only): list/get/create/save/delete sets, `POST /api/files?name=` for uploads (25 MB max, image or audio only), `GET /api/export/:id` (a `.proquiz.json` with the files inside as base64), `GET /api/export` (every quiz the host made in one file, **Export all quizzes**) and `POST /api/import` (one or many; answers `{id, ids, count}`). Saving is allowed with problems (drafts), but only valid quizzes can be chosen in the lobby (`chooseSet` host message). Saving the quiz that's on show in the lobby reloads it there. A new game keeps the last quiz and settings from the autosave. `state.setId` tracks which quiz is loaded.

## Editor page

(`/editor`, `public/js/editor.js`): the quiz list, the board as tiles, and a `<dialog>` per question with the picture and clip pickers. Everything that reads or changes a quiz goes through `api` from `public/js/quizapi.js` (`list`, `get`, `create`, `save`, `remove`, `setArchived`, `upload`, `importFile`, `exportDownload(id|null)` for the Export buttons, `fileUrl`, `lang`, `brand`, `sizeOf`, the picture and song search): `httpApi` over `/api/` on the laptop, `browserApi` on the website.

**On the website** (`HOSTED` in env.js, `docs/dev/web-plan.md` §2): `browserApi` wraps `createBrowserStore()` from `public/js/store-browser.js`, which keeps the host's quizzes in IndexedDB (`proquiz`: `sets`, `files` named by content hash through `crypto.subtle`, `meta` for the archived ids and `lastExport`) with the same behaviour as `store.js` on top of `lib/store-core.js`; the built-ins come from `/sets/<id>.json`. Differences the editor sees: `upload()` first shrinks a JPG/PNG photo over 1920 px to a 1920 px JPEG (`shrinkPicture()`; a PNG with see-through parts stays PNG, smaller pictures and GIF/WebP/SVG are untouched) and refuses a file over 8 MB (`edUploadFailedWeb`); `fileUrl()` gives an object URL (the store warms them on `get()`/`list()`); exports are built in the browser and downloaded as Blobs with the laptop's file names (`app: null` in the header); the picture and song search go through this browser's room (`roomCall()` in quizapi.js; media-and-pictures.md "On the website"); the About fold shows "Pictures and clips: 0.3 MB of 48 MB" (`.ed-media-size`, also in the fold's status; hidden for built-ins) and the problems box adds `edMediaOver`/`edMediaFileOver` when the files wouldn't fit a room (`MAX_ROOM_MEDIA`/`MAX_ROOM_FILE` in lib/room.js); every save, change and export is announced on `BroadcastChannel('proquiz-store')` so the host lobby reloads its list and the quiz on show; and `public/js/backup.js` shows the `#backup` banner (editor and host lobby) when there is an own quiz and nothing was exported for 30 days (or ever), or `navigator.storage.persist()` was refused, with Export all quizzes (any export records `lastExport`) and Not now (this visit). `refreshBackup()` runs after every list load and export.

**Layout (2026-10-11, "the screen gets a bit cramped"):** every editor dialog (`.ed-dialog`) is up to 1100px wide and starts with `dialogHead()`: a sticky `.ed-dialog-head` with the title and a 48px × (`.ed-dialog-close`, `aria-label` `edClose`), which calls `dialog.close()`, so the dialog's `close` handler (save, stop a preview, redraw) runs exactly as for Done or Cancel; the `.ed-dialog-actions` bar is sticky at the bottom, and only the form between them scrolls. The kind chooser (`chooseKind()`) has the same × (`closeButton(() => dialog, 'cancel')`). The question dialog is `.ed-q-body`: `.ed-q-main` (the words: `.ed-q-row` with Points + Special tile or Seconds + Points, the question in `.ed-q-text` which grows with its text, the answer or the answer rows) on the left and `.ed-q-media` on the right from 1000px, one column below; a board question's two pictures share a row and the clip, the slowly-appearing block (`.ed-unveil-box`, seconds and Pixels/Blur on one row) and the trim bar span both (`.ed-media-wide`; empty boxes are `display: none`). The text fields carry `name` (`question`, `answer`, `points`, `category`, `special`), which the suites use. On the main page the description, cover and languages sit in the folded `<details class="ed-about-fold">` "About the quiz" (`aboutFold()`, summary status from `aboutStatus()`, open state in localStorage `proquiz.edAboutOpen`), so the board or the sections start right under the quiz name; the tests open it with `openAbout()`. Screenshots `editor-space-question-*`, `editor-space-board-*` (e2e.mjs) and `editor-space-quick-*` (e2e-quick.mjs) at 1280×800 and 1920×1080.

**New quiz** (`#new-quiz`, the one button for both kinds) opens **What kind of quiz?** (`chooseKind()`: a `pq-modal` with two big `.ed-kind` cards, `.ed-kind-board`/`.ed-kind-quick`, each with a small inline SVG picture drawn in CSS-variable colours (`boardPicture()`/`quickPicture()`); Esc or Cancel = nothing) and `newQuiz()` then calls `createQuiz(blankSet())` or `createQuiz(blankQuickSet())`. The lobby's **New quiz** link (`#new-set` in `.picker-row`, next to **Edit**) opens `/editor?new`, which shows that pop-up on load and tidies the address with `replaceState`. A Quick quiz (`quick()`) shows section cards instead (`renderSections()`: name, seconds per question, the questions as rows with ▲ ▼ ×, Add a question, Add a section); `catsOf()` returns the sections, so the problem marks and texts work the same, and `openQuestion()` uses `quickFields()` (**Kind of question** pills `name=type` (`.ed-kind-pills`: Pick one / Tick all that are right / Put in order; `sync()` writes `q.type` only for multi/order), question, 4 answer slots in their colours and shapes with a **Right** checkbox each (several may be ticked; for "Put in order" the checkboxes are hidden and `.ed-opt-n` places `1.`–`4.` show instead, and the hint switches `edOptionsHint`/`edOptionsHintMulti`/`edOptionsHintOrder`), seconds, points select, picture and clip). Empty answers are saved out, so the ones after a gap move up in the game: the dialog says so while there is a gap (`edOptionsGap`) and moves them up itself when focus leaves the answers block (`moveUp()`, `edOptionsMoved`; not on each field's blur, which would move text under a click on **Right**), the right marks moving with their answers. The question rows show a chip per right answer (numbered chips in order for a "put in order" question) and a kind badge (`edMultiBadge`/`edOrderBadge`). It autosaves 600 ms after each change. Completely empty questions and categories aren't marked red, just counted. Use `fill()` from ui.js instead of `replaceChildren()` when a child might be null.

## Description and cover picture

(part of the quiz file, both kinds): `set.description` (plain text, ≤ `MAX_DESCRIPTION` 300 letters, `bad-description`) and `set.cover` (a picture file name like `image`, `bad-cover`), checked in validate.js, kept right after the title by `clean()` in lib/store-core.js (trimmed, cut, a broken cover dropped), counted by `usedFiles()` so exports carry the cover and its credit (`set.credits`, from the free picture search). The list summary (`/api/sets`) carries `description` (the first line) and `cover`. Editor: `aboutBlock()` under the quiz name (textarea, cover with Choose a file / Find a free picture / Remove, `.ed-about`, `.ed-cover`); the list shows the cover as a slim banner across the top of the row (`.ed-item-thumb` in `.ed-item.with-cover`; a thumbnail beside the words left too little room in the 280px column) and `.ed-item-desc`; the row is a one-column grid of `minmax(0, 1fr)` with the title clamped to two lines and the description and status line to one, so a long title or a cover can never widen the list past its column or push **Archive** out of view (`test/e2e.mjs` checks this at 1280px and 390px, glass on and off; screenshots `editor-list-covers*.png`). Host lobby: `#quiz-about` under the picker (`renderQuizAbout()`, the cover and the description); `displayView`/`quickDisplayView` pass both, but the TV lobby doesn't show them (it has no quiz title there); phones get nothing.

## Archive

(personal to this computer, never in a quiz file or an export's `set`): `<data dir>/archived.json` `{v: 1, ids}`, read by `archivedIds()`/written by `setArchived(id, on)` in store.js (built-in samples can be archived too; `remove()` takes a deleted quiz off the list). `/api/sets` entries carry `archived`; `PUT /api/sets/:id/archived {archived}` (404 for an unknown quiz). Editor list: every row (`.ed-row`) has **Archive**/**Bring back** (`.ed-archive`), archived quizzes sit in the folded `#quiz-archived` "Archived (n)" `<details>` at the bottom. The lobby's picker leaves archived quizzes out unless one is the chosen quiz (`view.setId`), so the lobby is never broken.

## Export file format

(`lib/fileformat.js`, documented in `docs/file-format.md`): `{proquiz: FORMAT_VERSION (1), app: <ProQuiz version>, exported: <ISO date>, set, files}` or, for export all, `{…, sets: [{set, archived?}], files}` with shared files once; built-ins are never exported. Adding an optional field keeps the version; a reshaped field bumps `FORMAT_VERSION` plus a step in `UPGRADES[n]` (format n → n + 1) that `upgradeExport()` chains on import. A newer file is refused with `quiz-too-new` (the editor says `edImportTooNew`); a plain quiz without `proquiz` still imports. `createStore(dataDir, {version, format})` takes the app version and, for tests, pretend upgrade steps. Tests: `test/export.test.js`.
