# Look and branding: the stage, glass, colours, avatars, sounds, music, pop-ups

The visual language (`public/style.css`), the glass look, branding (`brand.js`), team colours, avatars (`lib/avatar.js`, `public/js/avatar.js`), sounds (`public/js/sounds.js`), background music (`public/js/music.js`), ProQuiz's own pop-ups and the top bar.

## Look

a modern game-show stage: deep ink-violet, one soft stage light from above, glassy rounded tiles, pill buttons, and team colours as the loudest thing on screen. One dark theme on purpose (it is made for a TV). Colours are CSS variables in `:root` in `public/style.css`. Fonts are Unbounded (wide display face for headings and numbers) and Atkinson Hyperlegible (text), bundled in `public/fonts/` so the game works offline. Never load anything from the internet (the four exceptions: the editor's picture search and song search, see media-and-pictures.md; the host's new-version check and the host's own "Update now" download of a ProQuiz release, see update-and-release.md). Tap targets are at least 48px.

## Glass look

(setting `glass`, on by default; lobby tick in `#group-look`, status `#look-status`): Apple-style frosted glass, all in the `body.glass` block at the end of style.css (`--lg-*` and `--glow-*` variables in `:root`). `setGlass()` in ui.js puts the class on `<body>` from `view.settings.glass` on the host, TV and phones (`phoneView` passes `glass`); the host also remembers it in localStorage (`proquiz.glass`) so the editor, which has no game state, follows it (`savedGlass()`). Real `backdrop-filter` only on big panels, bars and dialogs (`.tv-q`, `.settings`, `.host-side`, `.controls`, …) and the phone's buzzer/pick controls; the TV board tiles, buttons and pills fake it with gradients and a top highlight. The glow behind everything is two `::before`/`::after` layers moved with transform only (TV: tinted by the first teams' colours through `--glow-a/b/c`, set in display.js), and `prefers-reduced-motion` stops it. With the setting off nothing in that block applies, so the plain look stays as it was. The e2e takes `glass-on-*`/`glass-off-*` screenshots and prints the TV's frame times.

## Branding

(`brand.js`, the host's own logo, event name and accent colour): the user's, not a quiz's and not a game setting. Stored in `<data dir>/brand/brand.json` (`{v, name, accent, plate, logo}`) plus at most one `logo-<sha256 16 hex>.<png|jpg|webp|svg>` there (old ones deleted); never in exports or the autosave. `createBrand(dataDir)` (loaded in `startServer()`) keeps it in memory: `view()` = `{name, accent, plate, logo: '/brand/<file>' | null}`, sent as `brand` in **every** state message (host, TV, phones, also over the tunnel). Changed only through `/api/brand` (so laptop only, 403 on the tunnel listener): `GET`, `PUT {name?, accent?, plate?}` (`cleanBrand()`: name ≤ 60 letters, accent `#rrggbb` or null = ProQuiz violet), `POST /api/brand/logo` (raw bytes, `MAX_LOGO` 2 MB → 413 `logo-too-big`, read to the end first; the type comes from the bytes, `logoKind()`, else 400 `logo-bad-type`), `DELETE /api/brand/logo` (writes refused with `Sec-Fetch-Site: cross-site`, so another website open in the laptop's browser can't change it); each calls `onBrand` → `hub.broadcast()`. `/brand/<file>` (only `LOGO_FILE` names) is served on both listeners with `logoHeaders()`: the real type, `nosniff`, a `default-src 'none'; …; sandbox` CSP and an immutable cache.

**The logo is only ever shown with `<img>`** (`brandLogo()` in ui.js), never inlined, so an SVG's scripts can't run.

**Screens:** `setBrand(brand)` in ui.js (host, TV, phone; the editor fetches `/api/brand`) sets the accent CSS variables on `<html>` (`accentVars()`: `--light-rgb`/`--flare-rgb` from the colour, the flare from `ACCENTS` or 40° round the wheel, the light darkened until white text has 3:1; and every tone in `TONES` (`--bg`, `--bg-deep`, `--ink`, `--muted`, `--panel`, `--pale`, `--primary-ink`, `--light-2/3-rgb`, `--deep-0…4-rgb`) re-hued to it; no accent removes them, so the default look is exactly as before), `body[data-accent]`, `body.has-logo`, the phone's theme colour, and puts the logo in every `.wordmark` (`.wordmark.logo`). So style.css must use these variables (`rgb(var(--light-rgb) / a)`), never the violet values. TV: the logo big with the name in `#tv-brand` above "Scan to join" and in `brandBlock()` on the end screen and the Quick podium; during the game small in the corner (`body.logo-corner` gives `.tv-stage` room), but not in the lobby, at `over` or in single-screen mode. Phone: the logo and `#brand-name` in the join form's `.join-head`. Host lobby: in `#group-look` (titled **Look and branding**), `#brand` with the preview, `#brand-file`, `#brand-remove`, `#brand-plate`, `#brand-name` (saved 500 ms after typing) and the `#brand-accents` swatches (`ACCENTS` plus `#brand-color`); nothing there sends `settings` (the form's change handler skips `#brand`). Tests: `test/brand.test.js`, `test/e2e-brand.mjs` (screenshots `brand-*.png`).

## Team colours

`COLORS` in lib/game.js: 16 (the 8 Apple-style colours for dark screens since 1.7, plus lime, teal, lavender, white, caramel, steel, mint and raspberry since 2.2; the index also picks the buzz note, `TEAM_NOTES` in sounds.js has 16). `inkFor()` picks dark or white name text; `test/quick.test.js` checks every colour against the stage and its text. `MAX_TEAMS` is 8 (a board quiz: 8 teams, each its own colour, any of the 16); a Quick quiz takes `MAX_PLAYERS`. The phone's `.swatches` is a 4 × 4 grid of 48–64px circles. `newColor()` turns a pre-1.7 colour (`OLD_COLORS`) into its new version: used by `join`, `resume()`/`summary()` in server.js and the phone's remembered colour. Keep `OLD_COLORS` so old saved games and phones still work.

## Avatars

(a Quick quiz player's face, a board team's **mascot**; same data and builder): `lib/avatar.js` has the parts (`AVATAR_PARTS`: skin 6, hair 8 (0 = bald), hairColor 6, eyes 5, mouth 5, glasses 4 and hat 6 (0 = none)), `isValidAvatar()`, `cleanAvatar()`, `randomAvatar()` (glasses and hat off about half the time), `avatarKey()` and `avatarOf(team)` (`{avatar}` or `{}`, spread into views so teams without one look exactly as before). `join {…, avatar}` is optional; a bad one throws `bad-avatar`; joining again without one keeps it. It is part of the team object, so autosave, undo, restart, resume and the resume list (`summary()`) carry it, and every view and standings entry (`standings`, `standingsBefore`, `fastestOf`, `neighbours`, `you`, `teams`) has it. `public/js/avatar.js` draws it: `avatarSvg(a)` is SVG text (flat fills only: no filters, blurs or gradients; layers: shoulders, hair back, ears, head, cheeks, eyes, mouth, hair front, glasses, hat; a cap or beanie hides what would stick through it, and a bun or mohawk makes room for a crown or party hat), `avatarEl(a, cls)` a cached `<span class="avatar">` (or null). The tables (`SKINS`, `HAIRS`, `HAIR_COLORS`, `EYES`, `MOUTHS`, `GLASSES`, `HATS`) must have exactly `AVATAR_PARTS` entries (`DRAWN`, checked by `test/avatar.test.js`). The coin's background is CSS (`.avatar`: the team colour, or a darker circle on a plate; glass adds a shine), 1em by default, sized per place in the "avatars" block of style.css.

**Phone:** `#avatar-field` on the join form (between the name and the colours): the preview in the chosen colour, the dice `#avatar-random`, `#avatar-edit` (Customise/Done) opening `#avatar-builder` with a tab per part and a tile per option (hair colours as dots); saved in `proquiz.team.avatar`, random on the first visit, always sent with `join`; the header `#me` shows it.

**TV:** lobby plates (newest player first; `.tv-lobby.crowd` over 12 players, `.packed` over 20 and `.horde` over 40 make everything smaller, and over `LOBBY_PLATES` 48 only the newest show plus "+ n more", so 100 fit), the top 5 and standings (`rankFace()`: the face with `.rank-n` as a corner badge, so the top 5's FLIP still finds `.rank-n`), the podium (`.step-face`), the fastest plate, the score strip, buzzer and result plates, the final's teams and judge cards, the end list.

**Host:** the lobby list, score rows, the Quick quiz side list, rank lists, the fastest plate and the resume list.

## Sounds and flashes

these are driven by `state.event` (`{seq, type, ...}`). Clients react when `seq` changes. Sounds are synthesized in `public/js/sounds.js` (no files), and each team's buzz is a note chosen by its colour index.

**The TV plays the sounds.** The host laptop plays them only when no TV screen is connected (`displays === 0` in the state message). Both show a "click to turn on sound" pill until the browser allows audio. The `sound` setting (key M) turns them off, and `soundVolume` (0–100, default 80; the lobby slider `#sound-volume-setting`, hidden when sound is off) sets their loudness through `setSoundVolume()`/`soundGain()` in sounds.js (called on every state message by the host and TV pages): 80 gives gain 1.0, a little louder than the fixed 0.8 before 2.3, 100 gives 1.25, and the shared limiter in `audioGraph()` keeps the peaks from clipping. The last 3 seconds of any timer tick.

## Background music

(`public/js/music.js`): nothing is stored in the game. `moodFor(view, now)` derives the mood from the phase (lobby, board, thinking and hot in the last 3 s of the buzz timer, answering, `calm` at `revealed` and the Quick `result`, `calmUp` at the Quick `ranks`, final/finalQ/judge, over; silent in `special` and whenever the question has a sound clip; `off` when `settings.music` is false). `MOODS` (exported) maps each mood to a built-in song (`SONGS`: day, tick, slow, party, and the ambient `glow` (no drums, 72 bpm) for calm/calmUp, 16-step patterns played by a lookahead scheduler on the shared AudioContext, with its own gain into the shared limiter from `audioGraph()` in sounds.js) with a set of layers and a level, or to the host's own file (`settings.musicFiles[mood]`, one of `MUSIC_MOODS`, uploaded via `/api/files` from the lobby). The same song only ramps its layers; a different song or file crossfades; a mood's `delay` holds a new song back (`calm` waits 1.2 s so the reveal chime stands alone, `over` waits for the fanfare). Optional song keys tune `playStep()` (`longBass`, `bassSteps`, `padAttack`, `padFilter`, `padSteps`, `bellEvery`, `arpType`, `arpGain`, `arpOctave`); left out, they give the old sound, so the first four songs sound as before. Files that fail to load fall back to the built-in song. It plays where the effects play (the TV, or the host when `displays === 0`), and `syncMusic` runs on every update plus every 250 ms. `body[data-music]` shows the mood for tests. Settings: `music`, `musicVolume` (0–100, default 80 since 2.3, was 35; `louderSettings()` in server.js moves a save that is still at 35 and has no `soundVolume` yet to 80, once), `musicFiles`; the B key toggles music. The TV reuses the slowly-appearing-picture canvas between updates (no flash).

## Pop-up questions

never the browser's `confirm()`/`alert()`/`prompt()`. Use `ask({title, text, ok, cancel, danger})` → `Promise<boolean>`, `tell({title, text})` and `askNumber({title, text, value, preview, allowZero})` → `Promise<number|null>` from ui.js: a `<dialog class="pq-modal">` opened with `showModal()` (built fresh, removed on close; `danger` = red button and Cancel focused, otherwise the main button is focused, so Enter says yes; Esc = Cancel). Titles and button labels are the `dlg*` keys in i18n.js. While one is open (`modalOpen()`), the host page's keys (also those passed from the embedded TV) do nothing. The e2e tests answer them with `answerModal()` and fail if a browser dialog ever appears.

## Top bar

`.host-bar` (host and editor) is `position: sticky` (z-index 10: above the page, below the keyboard help and dialogs) and stays one row on a narrow window (the quiz title is hidden under 640px). The game screens' `calc(100vh - 73px)` heights assume its 73px.
