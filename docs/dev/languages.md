# Extra languages in a quiz

`lib/languages.js`, the `translations` on each item, `wantsText()` (the one relaxation of "phones never see questions"), the phone's language pills, the host's grey lines and the editor's Translations dialog.

## Extra languages in a quiz

(`lib/languages.js`, built 2026-10-11): `LANGUAGES` is a fixed list of 29 `{code, name, flag, rtl?}` with native names (Thai `th` "ไทย" included) and a small bundled SVG flag each in `public/flags/<flag>.svg` (never emoji: Windows browsers don't draw flag emoji; one sensible flag per language: en → gb, ar → the Arab League, fa → ir, ur → pk, ti → er, zh → cn, hi → in, tl → ph, so → so).

**Data model:** `set.lang` (the main language, `mainLang()`, 'en' when missing), `set.languages` (the added codes, `languagesOf()`: known, not the main one, no repeats) and `translations: {"<code>": {…}}` **on the item it translates**: the quiz `{title, description}`, a category/section `{name}`, a board question `{question, answer}`, a Quick question `{question, options}` (by index, `""` = missing), the final `{category, question, answer}`. No format version bump; `clean()` in store.js writes `lang`/`languages`/`translations` only when there is something (a quiz without languages saves byte-identical to before) and remaps a Quick question's translated options with the same `keep` that drops its empty options (`cleanItemTranslations(…, {options: true, keep})`). Helpers: `textOf(item, lang, field)` and `optionsOf(q, lang)` fall back per field/option to the main text; `translationSlots(set)`/`translationItems(set)` give every non-empty text a **stable id**: `t`, `d`, `c0`, `2:c0`, `q0-1`/`a0-1` (`2:q0-1` on round 2), `f-c`/`f-q`/`f-a`, Quick `s0`, `sq0-1`, `o0-1-2`; `getTranslation`/`setTranslation` by id, `slotTranslation`/`setSlotTranslation` by slot, `missingTranslations(set, lang)`, `removeLanguage(set, lang)`, `cleanTranslations(set)`, `browserLang(tag)`.

**Rules:** `join {…, lang}` keeps a known code on `team.lang` (unknown ignored, joining again without one keeps it); the phone action `language {lang}` (in `PHONE_ACTIONS` and `SHARED`, no `remember()`) changes it.

**`wantsText(state, team)`** in game.js is the one rule that relaxes "phones never see questions": the language code when the setting `quizLanguages` is on (default true; lobby tick `#languages-setting` in the Quiz block, shown only when the quiz has extra languages), the team chose one, it isn't the main language and the quiz has it; else null. `languageChoice(state)` = `{main, extra}` or null is `view.languages` on every phone (the join form's pills). Board `phoneView`: `textLang`, `text: {question, answer?}` (the question from `reading`, the answer at `revealed`), the final's `category`/`question` (from `finalQuestion`)/`rightAnswer` (when the TV shows it) and the picking board's category names in that language. `quickPhoneView`: a translated player always gets `q.question` and `q.options` in their language (even with `quickPhoneText` off), the options through `shownOptions(s, lang)` so they follow the "put in order" shuffle; `sections` names translated. The TV (`displayView`) is always the main language.

**Phone** (`phone.js`): `#lang-field` pills with flags on the join form (default: the remembered `proquiz.team.lang`, else the browser language if offered, else main), the header `#lang-pill` (flag + code) opening `#lang-menu`; the phone's own UI language follows the choice only for en/no and only when it differs from the main language (`uiLang()`); translated text nodes carry `dir="auto"` (RTL languages); `.phone-text` with `.phone-question`/`.phone-answer`.

**Host** (`host.js`): `flagBadge(team)` in the lobby list, the score lists and the final rows; `translationLines(item, field)` = small grey `.host-tr` lines (flag + text) under the question and the answer for the languages teams have picked (`usedLangs()`), and under each Quick option (the shown order); `renderQuizAbout()` adds "Also in: 🇳🇴 Norsk …" (`.quiz-langs`, flags as SVG).

**Editor** (`editor.js`): `languagesBlock()` under the description (main-language select, excluding added ones; `.lang-chip` per language with flag, "n missing", **Translations**, × asking with `ask({danger: true})`; **Add a language** → `openLanguagePicker()`, a `pq-modal` grid of flag buttons, then straight into `openTranslationsDialog(code)`: the static `#tr-dialog` with `.tr-row`s (main text left, `textarea[data-id]` right, `dir=auto`), **Show only missing**, the count, autosave via `changed()`); `quickFields()` keeps translated options per slot (`trSlots`) so `moveUp()` and `sync()` move them with their options.

**Translate with AI** (`openTranslateAiDialog()`, reusing `#ai-dialog`): `buildTranslateRequest(set, lang)` in aiquiz.js lists only the missing texts as `{id, text}` pairs; `parseTranslation(text, set, lang)` fills only empty slots by id (never overwrites, unknown ids ignored; accepts `{translations: [...]}`, a bare list or an id → text object; `nothing-filled` otherwise).

**Fonts:** the `--display`/`--text` stacks name system fonts with Thai, Arabic, Devanagari, Ethiopic and CJK letters after the bundled ones, so a translation never shows as boxes. Samples: Norwegian in `sample`/`quick-sample`, English in `eksempel`/`lynquiz`. Tests: `test/languages.test.js`, the "languages:" tests in game/quick/server/export/aiquiz tests, and the browser tests (`phone-lang-*.png` incl. `phone-lang-thai`, `host-lang-*.png`, `editor-languages*.png`).
