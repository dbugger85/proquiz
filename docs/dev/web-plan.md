# Hosted ProQuiz (the website version): plan

**This is the decision record.** How the website works now is in `web.md`; read that for anything you change. This file keeps the owner's decisions, the findings, the free-plan numbers (§9) and the phase-by-phase status lines with every difference from the plan.

Planned with Fable on 2026-10-15; the owner accepted every recommended default the same day. The website runs **alongside** the laptop version from **one codebase**. The laptop version must not get worse: `npm test` and the full `npm run e2e` stay green after every phase.

- Hosting: **Cloudflare Workers + Durable Objects, free plan** (one Durable Object per game room); the pages are Workers static assets.
- **No accounts.** Quizzes, pictures and clips live only in the host's browser (IndexedDB, `navigator.storage.persist()`). The server keeps a game in memory while it is played and stores nothing, not even counts.
- `.proquiz.json` import/export in the browser, same format as today (`docs/file-format.md`), so files move freely between laptop and website.
- Players and the TV join with a room code (and QR). The host is recognised by a secret key kept in the host's browser.

## 1. Architecture

### 1.1 Runtime-neutral hub (`lib/hub.js`)

Move from `server.js`: `HOST_ACTIONS`, `PHONE_ACTIONS`, `REACT_EVERY_MS`, `CLOCK_*`, `PIN_TRIES_PER_MINUTE`, `louderSettings`, `pickSettings`, `summary`, `quickPlayed`, `createHub`. Keep `isLocal`, `sameSite`, `fromLaptop`, `autosaver`, `serveFile`, `startServer` in `server.js`.

| Option / message | Change | Why |
|---|---|---|
| `connect(ws, req, {remote, local})` | `local = opts.local ?? (!remote && fromLaptop(req))`, with `fromLaptop` passed in from server.js as an option, so the hub never reads `req.socket` | a DO has no Node request |
| `hostKey` | hello `role:'host'` accepted when `c.local \|\| (hostKey && msg.key === hostKey)`; else `error bad-host-key` (new `err-bad-host-key`). 5 wrong keys/min → ignore host hellos for a minute | host identity on the web |
| `hosted: true` | on hello, phones get `c.remote = true` (PIN, `slackCap`, `answerGrace`, `needPin` work unchanged); the display view blanks `remotePin` (anyone with the code can open the TV page; the host screen shows the PIN); the host lobby hides the "elsewhere" tag | reuse the tunnel rules |
| `cmd {type:'loadSet', set, setId}` | `validateSet(set)` → `set-has-problems`; `JSON.stringify(set).length > MAX_SET_BYTES` (600 KB) → `set-too-big` | replaces `chooseSet` (needs `store`) |
| `restore {saved}` (host, lobby, no teams yet) | same shaping as the constructor's `saved` handling, then `broadcast()` | autosave comes back from the host browser |
| `clockEveryMs`, `clockBurst` | options, defaults as now | fewer DO requests |
| `save(state)` | unchanged; the DO passes a debounced "send to host" | autosave replacement |

The `ws` surface the hub uses stays exactly: `send`, `readyState === 1`, `on('message'|'close'|'pong')`, `ping()`, `terminate()`. Node `ws` needs no wrapper.

### 1.2 Socket adapter (`web/socket.js`, ~50 lines)

Wraps a Cloudflare `WebSocket` into that surface. Strings only; close on binary or > 64 KB from non-hosts, 1 MiB from the host. Cloudflare sockets have no `ping()`, so `ping()` sends `{"type":"ping"}` and an incoming `{"type":"pong"}` becomes `emit('pong')`. `public/js/net.js` gets one line: `if (msg.type === 'ping') return ws.send('{"type":"pong"}')`. Node never sends `ping` messages, so the laptop is untouched.

### 1.3 Durable Object: non-hibernating in v1

- `web/room.js` (`class Room`, ~250 lines): one `createHub({hosted, hostKey, set: sample, info, save, clockEveryMs: 20000})` with `sets/sample.json` imported as a JSON module; `fetch()` handles `/ws` (WebSocketPair, `accept()`, `hub.connect(wrap(server), null, {remote:false, local:false})`), `GET /files`, `PUT /files/:name`, `GET /files/:name` (Range); all key-checked except GET file and ws.
- No hibernation in v1 (it would drop the in-memory game and timers; needs `ctx.storage`, alarms, `serializeAttachment`, ~300 lines). Optional Phase 8.
- Idle rule: no host connection for 30 min → `bye` to all, close sockets.

### 1.4 Room codes and host key (no server storage)

- Host page: `key = base64url(16 random bytes)`; `code = base32(sha256(key)).slice(0,6)`, alphabet without 0/O/1/I (`lib/room.js`, pure, shared). DO = `ROOMS.idFromName(code)`.
- The DO verifies a host by recomputing the code from the key. An evicted room re-accepts the same key. A DO that already has a different key → `room-taken`, the host page makes a new key. Key in `localStorage proquiz.room = {code, key, at}`; sent in the hello and as header `x-proquiz-key` on uploads; never in a URL.

### 1.6 Hosted mode in the pages (`public/js/env.js`, ~40 lines)

- `ROOM` = code from `/r/<code>` (phone, TV). `HOSTED` = hostname is not `localhost`/an IP literal (host, editor). Matches the laptop server: `sameSite()` already refuses host/editor on other hostnames, and the tunnel only serves phones/TV.
- `wsPath(room)` → `/r/CODE/ws` or `/ws` (net.js gets a `path` option). `fileUrl(name)` → `/r/CODE/files/x` or `/files/x`; adopt in `clip.js`, `display.js`, `music.js`, `host.js`, `editor.js` (which uses blob URLs from the browser store when hosted).

## 2. Browser storage

- `public/js/store-browser.js` (~400 lines): IndexedDB `proquiz` v1, stores `sets` (`{id, set, updated}`), `files` (`{name, blob, type}`), `meta` (`archived`, `brand`, `autosave`, `lastExport`). Same method names as `createStore()`: `list`, `get` (built-ins fetched from `/sets/<id>.json`), `save` (returns `validateSet(set)`), `create`, `remove`, `addFile(name, bytes)` (sha256 via `crypto.subtle`, same 16-hex naming, `.jpeg`→`.jpg`, `FILE_NAME` check, size cap), `url(name)` (object-URL cache), `exportPackage`, `exportAll`, `importPackage`, `archivedIds`, `setArchived`, `persist()`, `estimate()`, `sizeOf(set)`.
- `lib/store-core.js` (~180 lines moved from `store.js`): `BUILT_IN`, `SAMPLE_ID`, `ID`, `MAX_FILE`, `clean`, `summary`, `slug`, `looksLikeSet`, `header(version)`, `packageSets(pkg, format)`.
- `public/js/quizapi.js` (~120 lines): `api = HOSTED ? browserApi : httpApi` with `list, get, create, save, remove, setArchived, upload(file), importFile(text), exportDownload(id|null), fileUrl(name), lang(), brand()`. `httpApi` wraps today's `call()`; `browserApi` wraps the store and builds Blob downloads.
- Backup reminder in the editor and host lobby (hosted only): ≥1 own quiz and `lastExport` missing or older than 30 days, or `persist()` refused (Safari note: deletes after 7 days without a visit). Keys `backupReminder`, `backupNow`, `storageNotKept`.

## 3. Media during a game

- Host browser → `PUT /r/CODE/files/<name>` (HTTP, because WebSocket messages are capped) → DO `Map<name, {bytes, type}>` → TV/host fetch `/r/CODE/files/<name>` with Range. Phones never get names.
- `syncRoom(set)` in `host.js` (~90 lines): `GET /r/CODE/files` → upload `usedFiles(set)` minus what the room has, with a progress line (`uploadingMedia {n, total}`), then `cmd loadSet`. Also before `start` and after `restore`. `mediaTooBig` when over the cap.
- Caps: 8 MB per file, 48 MB per quiz, `MAX_SET_BYTES` 600 KB for the quiz JSON. "About the quiz" shows "Pictures and clips: 12 MB of 48 MB" when hosted; the host picker disables a quiz over the cap.
- Shrink on add (website only): canvas resize to ≤1920 px, JPEG q0.85 for jpg/png photos; skip gif/svg.

## 4. Picture and song search in the Worker

- Node-only bits: `isIP` from `node:net` (`pictures.js`, `songs.js`) → regex helper in `lib/safeurl.js` (also hosts `safeUrl()` once); `Buffer.from/concat` → `Uint8Array` concat.
- `store` becomes optional: with `store: null`, `fetch()` returns `{bytes, kind, credit}`; the route answers bytes with `Content-Type` and `x-proquiz-credit`; `browserApi` hashes and stores them. Laptop path and its tests unchanged.
- If the free plan's CPU limit bites on big downloads, run them in the room DO (`/r/CODE/api/pictures/fetch`, key-checked). Upstream limits per shared Cloudflare IP may give `rate-limited` more often.

## 5. Resume after refresh; DO evicted mid-game

- The DO sends `{type:'save', saved:{v:1, savedAt, state}}` to host connections (debounced); `host.js` writes it to IndexedDB.
- Host refresh with the DO alive: hello with the key → current state.
- DO evicted: the next connection gets a fresh lobby. The host page, holding an autosave with teams, runs `syncRoom` and sends `restore`; the lobby shows "Continue the game from 19:42?". Phones and TV reconnect by themselves and `resume()` puts phones back in their teams.
- Host leaves for good: the room closes after 30 min; the autosave stays in the browser for a new room later.

## 6. Security

| Topic | Rule |
|---|---|
| Room code guessing | 6 chars, 32 symbols; a guessed code only reaches the phone lobby (no questions/answers) and the TV page (PIN blanked there). Optional 4-digit PIN, 10 wrong/min per room |
| Host key | 128-bit random, checked by hash → code; wrong keys limited per room; never in URLs; `hostView` and `save` only to key holders |
| No `POST /rooms` | codes are made in the browser; a DO refuses a second host with a different key |
| Sizes | WS inbound 64 KB (non-host), 1 MiB (host); `MAX_SET_BYTES`; file/quiz caps; `MAX_PLAYERS`/`MAX_TEAMS`; `REACT_EVERY_MS` |
| Who sees what | `viewFor` unchanged; add a hub test that the hosted TV view has no `remotePin` |
| Served files | only `FILE_NAME`/`LOGO_FILE` names, `nosniff`, type by extension (`lib/mime.js` = today's `TYPES`) |
| Headers | `_headers`: CSP `default-src 'self'; img-src 'self' blob: data: https:; media-src 'self' blob: https:; connect-src 'self'`, `X-Content-Type-Options`, `Referrer-Policy` |

## 9. Free-plan limits to verify before Phase 1

1. Workers Free: requests per day; CPU time per invocation (matters for picture downloads).
2. Durable Objects on Free: SQLite-backed availability, requests/day, GB-s duration/day; whether each incoming WebSocket message on a non-hibernating DO counts as a request. Compute a 100-player Quick quiz × clock pings at 20 s × 2 h.
3. WebSocket message size limit and DO memory.
4. Request body limit for uploads; subrequest limit for search routes.
5. Static asset file count and size limits; that only `run_worker_first` paths count as Worker requests.
6. DO eviction while sockets are open and after the last one closes.

**Checked 2026-10-15 (developers.cloudflare.com):**

| Limit (Free) | Value |
|---|---|
| Worker requests | 100,000/day (reset 00:00 UTC); 10 ms CPU per HTTP request; 50 subrequests; 100 MB body. WebSocket messages through a Worker don't count, only the upgrade |
| Durable Objects | SQLite-backed only; 100,000 requests/day and 13,000 GB-s/day; over the limit, calls fail until the reset |
| WebSocket messages to a DO | Connect = 1 request; **incoming messages at 20:1** (also without hibernation); outgoing messages and protocol pings free. **Unclear:** whether the free 100k limit uses 20:1 or raw counts |
| Duration (non-hibernating) | wall-clock × 128 MB while sockets are open: a 2 h game ≈ 922 GB-s (7 %) |
| Sizes | incoming WS message up to 32 MiB; 128 MB memory; 30 s CPU per DO request |
| Static assets | free and unlimited; 20,000 files, 25 MiB each; `run_worker_first` takes path patterns and only those count |
| Eviction | idle DO after 70–140 s without incoming events; **every deploy restarts all DOs and drops all sockets** |
| Timers | `setTimeout`/`setInterval` allowed; a pending timer prevents hibernation |

A 100-player, 2 h Quick quiz (pong every 20 s + an action every 10 s): 108,000 incoming messages ≈ 5,500 requests at 20:1 (5.5 %), 922 GB-s (7 %). At 5 s pongs ≈ 10,900 (11 %). So one or two games a day fit comfortably **if** 20:1 applies to the free limit; counted 1:1, even one such game would run out.

Consequences for the build:
- Phase 1 accepts sockets with the hibernation API (`ctx.acceptWebSocket`, no extra cost): quiet lobbies and gaps stop counting duration, and `setWebSocketAutoResponse` handles keep-alive without waking the room. The clock-sync pongs stay app messages (they need timing), every 20 s.
- Never deploy during a game; the restore flow (§5) covers a restart anyway.
- Phase 7: run one real test game and read the request count on the Cloudflare dashboard. If raw messages are counted, the fallback is the Workers Paid plan (USD 5/month) or slower clock pings.

## 11. Risks

- How the free plan counts DO requests and duration (clock pings, non-hibernating duration) could cap 100-player Quick quizzes; verify before Phase 1, keep Phase 8 in reserve.
- Free-plan CPU per request vs big picture downloads; route through the DO if needed.
- Openverse/Wikimedia/Deezer anonymous limits on shared Cloudflare IPs.
- Safari evicts IndexedDB after 7 days unused and often refuses `persist()`; the backup reminder is the answer; say so in the README.
- WebSocket message cap vs a very large multi-language Quick quiz (`MAX_SET_BYTES` guards it).
- `wrangler` is a big devDependency; keep it out of `npm test`.
- The existing browser suites can't cover the website; `e2e-web` relies on DOM waits only.
- Wrangler bundling: no `new URL(..., import.meta.url)` in `web/*` (JSON imports instead).
