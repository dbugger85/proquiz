# File index

What each file is for. Test files are listed in tests.md.

| File | Purpose |
|---|---|
| `server.js` | Static files (`/` phone, `/host`, `/display`, `/editor`, `/lib/*`, `/files/*`), the WebSocket at `/ws` (handed to the hub), which connections count as the laptop's own (`fromLaptop`), the autosave file, the tunnel's listener, and printing the LAN address |
| `lib/hub.js`, `test/hub.test.js` | The hub: the one game and everyone connected to it (`createHub`), the WebSocket protocol, fair buzzing, resume, main menu, the PIN, `HOST_ACTIONS`. No Node modules, so the website version (web-plan.md) can run it too; its options for that (`hosted`, `hostKey`, `cmd loadSet` with `MAX_SET_BYTES`, `restore` (a finished game isn't offered; a quiz over `MAX_SET_BYTES` refused), `clockEveryMs`/`clockBurst`/`heartbeatMs`, the host's `brand {name, accent, plate, logo}` message kept in memory with `logoUrl(name)` for the logo's address) do nothing on the laptop. The tests use pretend sockets |
| `lib/brand-core.js` | The branding rules without Node, shared by brand.js, the hub and the website's browser store: `MAX_LOGO` (2 MB), `MAX_BRAND_NAME`, `LOGO_FILE` (`logo-<16 hex>.<png\|jpg\|webp\|svg>`), `NO_BRAND`, `cleanBrand()`, `cleanLogo()`, `isNoBrand()` |
| `lib/store-core.js` | The parts of store.js that don't touch the disk: `BUILT_IN`, `SAMPLE_ID`, the caps, `clean()`, the list `summary()`, `slug()`, `looksLikeSet`, the export `header()` and `packageSets()` (the import shaping); shared with the website's browser store |
| `lib/mime.js` | Content types by extension (`TYPES`, `typeFor()`), the logo's headers (`logoHeaders()`), and what kind of picture some bytes really are (`logoKind()`, `imageKind()`; no Node, so brand.js, pictures.js and the website share them) |
| `lib/safeurl.js`, `test/safeurl.test.js` | `safeUrl()` (an address the picture and song search may download from) and `isIP()` (Node's answers, without Node) |
| `lib/room.js`, `test/room.test.js` | The website's room codes: `newKey()`, `codeFor(key)` (sha256 → base32 without 0/O/1/I, 6 characters), `normalizeCode()`; pure, through `globalThis.crypto`. Also the media caps for a room, `MAX_ROOM_FILE` (8 MB) and `MAX_ROOM_MEDIA` (48 MB) |
| `lib/game.js` | Game rules, phases, scoring, undo, final round, and the per-screen views |
| `lib/validate.js` | Question set checks, shared by the server and the editor |
| `lib/crazy.js` | Kaosmodus: kinds, seeded random, placement, turbo tiles, last place |
| `public/js/specials.js` | Kaosmodus icons, rule text and question badge (TV, host, phones) |
| `store.js` | Quizzes and files on disk, the archived list, export and import, plus the editor's `/api/` (the pure parts are in `lib/store-core.js`). Built-in quizzes are listed in `BUILT_IN` (`sample` in English, `eksempel` in Norwegian, and the Quick quizzes `quick-sample` and `lynquiz`) |
| `lib/fileformat.js`, `docs/file-format.md`, `test/export.test.js` | The `.proquiz.json` export format: the version number, the upgrade chain for older files, the refusal of newer ones; the doc; the tests (round trips of a board and a Quick quiz with everything, byte-identical files, versions, export all, archiving, the louder defaults for old saves) |
| `lib/quick.js`, `test/quick.test.js` | Quick quiz rules and views (phases, answers, scoring, standings, resume), and their tests |
| `lib/tunnel.js` | Joining over the internet: finding, downloading and running cloudflared, reading its address, waiting until it can be found (server.js starts and stops it from the `joinMode` setting) |
| `sets/quick-sample.json`, `sets/lynquiz.json` | The English and Norwegian sample Quick quizzes (3 sections × 5 questions, with a picture that appears slowly (blur, 12 s), a clip, true/false, a double-points question, a "tick all that are right" question and a "put in order" question) |
| `scripts/build.mjs` | Packaging: `deno compile` per system (with `package.json` inside, for the version), plus a START HERE note, zipped into `dist/`, and `dist/SHA256SUMS.txt` for Update now |
| `lib/update.js`, `test/update.test.js` | New version notice: reading GitHub's latest release, comparing versions, the notes excerpt, the 6-hour cache; the tests with a fake GitHub, also against the real server |
| `lib/selfupdate.js`, `test/selfupdate.test.js` | Update now (the compiled program only): the safe download, SHA256SUMS.txt, the zip reader, writing ProQuiz.new, the `--version` check, the swap and its rollback, the restart as a child of the old process; the tests with a pretend release, shell-script programs and the real server |
| `lib/aiquiz.js`, `test/aiquiz.test.js` | Making a quiz with AI: the request text and the forgiving reader for pasted answers |
| `public/editor.html`, `js/editor.js` | Question editor (on the website on top of the browser store: the picture and song search through this browser's room, the size line in About the quiz, the backup banner) |
| `public/js/clip.js` | Sound clip player that follows `state.media`, and stops a trimmed clip at the end of its part |
| `public/js/rankanim.js` | Counting numbers and the Quick top 5's animation (TV, phones): `animateRanks()` (the old list → points count up → FLIP to the new order; each `.top-list li` is a 3-column grid, arrow | plate | empty `.move-pad` of the same width, so the plates sit centred under the title, `RANK_TIMES`, `body[data-rankanim]` = before/count/move/done for tests; `cancelRanks()` on any redraw). **The top 5's width** (owner feedback 2026-10-11: on a real 75" smart TV the plates were narrow pills with the names cut to one letter): `.top-list` is `width: 74vw; max-width: 1540px` in plain CSS (no `min()`, nothing that needs the browser to size the grid from its content), the arrow columns `10vh` and the plate column `minmax(0, 1fr)` (so about 60vw of plate), `.rank-plate` and `.standings-list li` use `minmax(0, 1fr)` for the name too, and `rankName()` in display.js adds `.long` to a name over 14 letters (set at 0.78em, so every name up to the 20-letter limit shows in full). `.standings` is `84vw` with a `max-width` the same way, and the podium's row is `minmax(0, 100%)` with only `.step-block` allowed to shrink, so a two-line winner's name no longer pushes the steps' points under the clip, `countTo()`/`shownCount()` for numbers on screens that are redrawn often (they write into `[data-count=key]`: the TV's score strip, the podium, the board's end list, the phone's `#score`), one shared soft tick (`sounds.countTick`; `sounds.swap` when rows move). Follows `prefers-reduced-motion` in JS (the CSS rule doesn't stop `el.animate()`) |
| `public/js/music.js` | Background music: `moodFor()`, the built-in songs and scheduler, the host's own files |
| `sets/sample.json`, `sets/eksempel.json`, `sets/files/` | The English and Norwegian sample quizzes (5×5, a 5×5 round 2, and a final), with two sample pictures and a generated sample tune |
| `lib/languages.js`, `public/flags/`, `test/languages.test.js` | Extra languages in a quiz: the language list with native names and flags, reading texts with fallback, the stable ids, missing counts, tidying; the small flag SVGs; the tests |
| `lib/avatar.js`, `public/js/avatar.js`, `test/avatar.test.js` | Avatars and mascots: the parts and checks (shared), the drawings, and their tests (rules, every option draws, the tables match, views and joins carry them) |
| `public/index.html`, `js/phone.js` | Phone: join form (name, avatar or mascot, colour), then the team-coloured buzzer screen. The team id is kept in localStorage (`proquiz.team`) |
| `public/host.html`, `js/host.js` | Host laptop: lobby (QR, teams, settings), then the board, the question with its answer, the scores (Let them pick, Change score) and the controls. On the website the branding block works on top of the browser store and `sendBrand()` (the logo into the room's file store, then the `brand` message, on every connection). `controls()` lists the buttons for the current phase and also drives the keys: Space arms or goes back to the board, Y correct, N wrong, R show answer, Esc put back, U undo, E end the board. `body[data-phase]` is set for the e2e test |
| `public/display.html`, `js/display.js` | TV screen: lobby (newest player first), board, question (zooms in once per question), the score strip, the "buzz takeover" (the frame floods in the colour of the team that buzzed), and the players' reactions floating up (`#reactions`). F toggles full screen |
| `public/js/net.js` | Reconnecting WebSocket client (`path` option, `/ws` by default) and the server clock offset; answers a `ping` message with `pong` for the website's server |
| `public/js/env.js` | Where a page runs: `ROOM` (from `/r/<code>`), `HOSTED` (the page is stamped `<meta name="proquiz" content="hosted">` by the web build, or the address isn't localhost/an IP), `setRoom()` (the host page says which room it made), `wsPath()`, `fileUrl()`, `pagePath()`; every page gets its addresses from here |
| `web/worker.js` | The website version's Worker (web-plan.md): everything under `/r/<code>` (the phone page, the TV page, the WebSocket handed to the room, the quiz's files: `GET /files` and `PUT`/`DELETE /files/<name>` to the room, `GET /files/<name>` from the room with the built-in `sets/files/` assets as the fallback), the editor's picture and song search handed to the room (`/r/<code>/api/pictures/*`, `/api/songs/*`)), `/api/` as 404, everything else a static asset. Wrangler bundles it with `lib/` (the one bundler in ProQuiz) |
| `web/room.js` | The room: one Durable Object (`Room`) per room code holding one hub in memory, nothing stored. The host's logo goes into the file store under its `logo-…` name with the laptop's rules (`MAX_LOGO` → 413 `logo-too-big`, the bytes must be the kind the name says → 400 `logo-bad-type`), and the hub's `logoUrl` points the screens at `/r/<code>/files/<logo>`. The first host whose key gives the code claims the room (`room-taken` for another key with the same code), sockets through the hibernation API (`ctx.acceptWebSocket`, `webSocketMessage`/`webSocketClose`), messages from one socket handled in order, a forgotten room (no host for 30 min, `ROOM_IDLE_MS`, or the `ROOM_IDLE_MS` variable; 5 min, `ROOM_EMPTY_IDLE_MS`, once nobody is connected and the lobby is empty) says `bye` with `reason: 'closed'` and closes, sockets from before a restart are closed so the pages reconnect; the game goes to the host's browser as `save` messages (`autosave()`, 250 ms after a change) and comes back with `restore`; phones and TVs in a room no host has claimed get `hostHere {here: false}` and `here: true` when one does; wrong host keys from hellos and the key-checked routes are limited per room (`keyBlocked()`, 5 a minute, then other keys get 429 `key-wait` / `bad-host-key` unread; the right key always works); a search's fetch body is capped. The quiz's pictures and clips in memory (`files`: list, `PUT` and `DELETE` with the host's key in `x-proquiz-key`, `GET` with Range and `nosniff`, 8 MB per file and 48 MB together or the `ROOM_MEDIA_BYTES` variable, gone when the room closes; `drain()` reads a refused body so workerd keeps the connection). The editor's picture and song search (`searchRequest()`: the laptop's routes under `/r/<code>/api/…` with the host's key and the same-origin rule; a fetch answers the bytes with `x-proquiz-name` and `x-proquiz-credit`; `upstreamFetch()` points pictures.js/songs.js at the pretend internet when the `UPSTREAM` variable names this machine, tests only) |
| `web/socket.js` | A Cloudflare WebSocket as the hub expects one (`send`, `readyState`, `on`, `ping()` as a `{"type":"ping"}` message with the page's `pong` answer as the event, `terminate`), with the size caps (64 KB, the host 1 MiB) and strings only |
| `web/headers.js` | The website's security headers (CSP and the rest), used by the build script (`_headers`) and the Worker |
| `public/home.html`, `js/home.js` | The website's front page (`index.html` once built): the room code to join on a phone or show on a TV, "Host a quiz", English/Norwegian |
| `wrangler.toml` | The Worker's config: `web/worker.js`, the static assets in `dist/web` (`run_worker_first` for `/r/*` and `/api/*`), the `ROOMS` binding to `Room`, the SQLite-backed class migration the free plan needs |
| `scripts/web-build.mjs` | Builds `dist/web`: `public/` (home.html → index.html, the phone page → join.html, every page stamped as hosted), `lib/`, the built-in quizzes and their files, `_headers` |
| `public/js/quizapi.js` | `api`: how the editor and the host lobby read and change quizzes (`list`, `get`, `create`, `save`, `remove`, `setArchived`, `upload`, `importFile`, `exportDownload`, `fileUrl`, `lang`, `brand`, `sizeOf`, the picture and song search): `httpApi` over `/api/` on the laptop, `browserApi` over the browser store on the website (`HOSTED`), which also exports `store` for the host page and runs the picture and song search through this browser's room (`roomCall()`, the found bytes shrunk and stored here). Downloads: the server's attachment, or a Blob through a hidden `<a download>` |
| `public/js/store-browser.js` | The website's quiz store (web-plan.md §2): IndexedDB `proquiz` (`sets`, `files`, `meta`) with the same methods as `store.js`'s `createStore()` on top of `lib/store-core.js` (built-ins from `/sets/<id>.json`, content-named files via `crypto.subtle`, export/import of `.proquiz.json` with base64 files, archive), plus `fileBlob`/`warm`/`url` (object URLs for previews), `persist()`, `estimate()`, `sizeOf()` against the room caps, `lastExport`/`markExported`/`backupStatus()` for the reminder, `autosave()`/`setAutosave()`/`clearAutosave()` (the room's `save` messages, `meta.autosave`), the branding (`brand()`, `setBrand()`, `setLogo()` (checked and content-named like brand.js, at most one logo file kept), `removeLogo()`; `meta.brand` with the logo as a file in `files`, never in an export), `BroadcastChannel('proquiz-store')` messages, and `shrinkPicture()` (big JPG/PNG photos to 1920 px JPEG before they are stored) |
| `public/js/backup.js` | The website's backup reminder: the `#backup` banner in the editor and the host lobby (an own quiz and no export for 30 days or ever, or the browser won't keep the storage), with Export all quizzes and Not now |
| `public/js/myroom.js` | This browser's room on the website: the secret key in `localStorage proquiz.room` and its code (`myRoom()` loads or makes one, `makeRoom()` makes a new one), used by the host page and by the editor's search |
| `test/fixtures/laptop-export.proquiz.json` | The sample quiz with a cover and a description as the laptop's `store.js` exports it, for the website's import test |
