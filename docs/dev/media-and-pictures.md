# Pictures, sound clips, slowly appearing pictures, the picture search and the song search

Files in questions (`image`, `answerImage`, `audio` + trim), the unveil, clip playback (`public/js/clip.js`), the editor's **Find a free picture** (`pictures.js`) and **Find a song clip** (`songs.js`), and the credits shown on the TV.

## Pictures and sound clips

a question (or the final) can have `image` (shown with the question), `answerImage` (shown only when revealed, and never sent to the TV before), and `audio` with an optional `audioStart` in seconds and an optional `audioLength` (seconds, `MIN_AUDIO_LENGTH` 0.5 – `MAX_AUDIO_LENGTH` 600, else `bad-audio`; `clean()` keeps both only with a clip): the trimmed part, left out when the clip plays to its end. The format version stays 1 (an optional field). They are plain file names (`IMAGE_NAME`/`AUDIO_NAME` in `lib/validate.js`) served at `/files/<name>` (with Range support), from `<data dir>/files/` first and then the bundled `sets/files/`. Uploads are named after their content (sha256, 16 hex characters). The TV loads pictures and clips early while the board shows. Phones never get file names. **On the website version** the files live in the host's browser and go into the game room before a quiz is played (`syncRoom()` in host.js, `/r/<code>/files/<name>` from the room's memory with Range, 8 MB per file and 48 MB per quiz): `docs/dev/web-plan.md` §3.

## Slowly appearing pictures ("unveil")

a question with `image` can have `unveil` (seconds, 1–120, `bad-unveil`) and `unveilStyle` (`UNVEIL_STYLES` in validate.js: `pixels`, the default and left out of the file, or `blur`; `bad-unveil-style`), checked by `checkUnveil()` for board tiles and Quick questions alike, and kept by `unveilOf()` in store.js only with a picture (the style only with `unveil` and never `pixels`). `unveilOf(src, capSeconds)` in game.js builds `q.unveil = {ms, done, since, style}`, and `syncUnveil()` (run in `apply()` after `syncMedia`) makes it run while `armed` (and during a solo answer) on a board, pause otherwise, and be complete at `revealed`; `openBuzzers()` adds the remaining unveil time to the buzz deadline.

**In a Quick quiz** (built 2026-10-11) `openQuestion()` in quick.js caps `ms` at the question's seconds (so the picture is clear by the time the clock runs out; the editor says so when the time is longer), it stays hidden through `ready`, runs through `open` and is complete from `result` (also when everyone answered early); `afterUndo()` into `open` and `resumeFix()` start it over with the clock; `quickDisplayView` carries `q.unveil`, and phones get nothing (they never get file names). Scoring is unchanged (`pointsFor`). The TV (`unveilCanvas(q, key)` in display.js, one code path for both kinds: key `c-i` or `quick-s-i`) draws a `canvas.q-img.unveil.pixels|blur` on the server clock: pixels through the block steps `STEPS` (a small canvas scaled up without smoothing), blur through `drawBlur()` (`ctx.filter = blur(r px)` on the 1280px canvas, `r` from `BLUR_MAX` 90 halving every 1/`BLUR_HALVINGS` of the time, redrawn when it changes by about 4 %, drawn a little bigger so the soft edge falls outside; a browser without canvas filters gets a downscaled-and-smoothed picture instead; `prefers-reduced-motion` sharpens in `STEPS.length` jumps instead of every frame). The canvas carries `data-step`, `data-pct` (0–100) and, for blur, `data-blur` for the tests. The clear `<img>` only goes on screen once the answer is out (board: `revealed`; Quick: from `result`, beside the bars in `.quick-mid.with-picture`). The host shows "Picture: n% clear" (`unveilLine()`, also in the Quick question view; `unveilWaitingQuick` during `ready`). The editor's control (`drawUnveil()`, under the question picture in both the board dialog and `quickFields()`): the tick, the seconds, the **Pixels** / **Blur** pills (`.ed-unveil-pills`, `name=unveilStyle`, small icons from `unveilIcon()`) and the note (`edUnveilHint`/`edUnveilHintQuick`/`edUnveilCapped`, kept up to date by `drawUnveilNote()` when the question's seconds change). Resume moves `since` to now. The word "unveil" is used so it isn't confused with `reveal` (show the answer). Not on the final question. Tests: `test/game.test.js`, `test/quick.test.js` ("a slowly appearing picture …"), `test/export.test.js`, and the browser tests (`tv-16-unveil-mid`, `tv-unveil-blur`, `quick-tv-unveil-pixels`, `quick-tv-unveil-blur`, `quick-tv-unveil-result`, `editor-unveil-style`).

## Clip playback

`state.media` (`{playing, seq}`) is set by `syncMedia()` in `lib/game.js` after every action. A new question starts its clip. A buzz or the final's judging pauses it, and the re-opened buzzers and the reveal play it on. `mediaToggle` (P) and `mediaRestart` (0, which bumps `seq`) are host actions. `public/js/clip.js` makes an `<audio>` follow that state. It runs on the TV, or on the host when no TV is open. Views carry `clip: {file, start, length?}` (`clipOf(src)` in game.js, used by `clipFor()` and `quickClip()`).

**Trimmed clips:** with `length` set, clip.js pauses the `<audio>` by itself at `start + length` (a timer set from the current time, with `timeupdate` as a safety net; `clipEnded()`/`clipTime()` for tests), while `state.media.playing` stays true (the game doesn't know the clip ran out); a new `seq` (key 0) or a new question plays the trimmed part again, and a false → true `playing` after the end (P twice, or the reveal after a buzz) starts it from `start` again. The host's clip line says "(from 1:05, 10 s)" (`mss()` and `lengthText()` in i18n.js).

**The editor's trim bar** (`trimBar()` in editor.js, drawn by `drawTrim(preview)` under the clip card; the owner's design, replacing the old "Start at" field): the whole clip as a track (`.ed-trim-track`, the length from the preview `<audio>`'s metadata, "Loading the clip…" until then), a 48px `role=slider` button at each end (`.ed-trim-handle.start/.end`: pointer capture drags, arrow keys ±`TRIM_STEP` 0.5 s, Page Up/Down ±5 s, Home/End), the chosen part lit (`.ed-trim-range`), the times as m:ss (`edTrimTimes`, or `edTrimWhole` for the whole clip), and **Try it** (`.ed-trim-try`: plays only the chosen part on the preview element with a moving `.ed-trim-playhead`, says Stop meanwhile). Times are stored to a tenth of a second; the right handle within 0.05 s of the end means no `audioLength`; a quiz with only `audioStart` shows the left handle there. Built-in samples show the bar disabled (`edTrimHintSample`).

## Free pictures

(`pictures.js`, the editor's **Find a free picture**; one of the exceptions to "never load anything from the internet", like Find a song clip below: only the editor, only on the laptop, only when the host searches; the game stays offline): `createPictures({store, fetchImpl, now, lang})` (wired in `startServer({pictureOptions})`, tests pass a fake `fetchImpl`) has `search({q, source, page, license, lang})` → `{results: [{id, title, author, license, nc, licenseUrl, source, sourceUrl, thumb, fallback, width, height, provider}], page, more}` and `fetch({source, id})` → `{name, kind: 'image', credit}`. Routes in `apiHandler` (so laptop only, 403 on the tunnel listener, and also 403 for any `Sec-Fetch-Site` but same-origin/none, since a search costs the laptop's upstream quota): `GET /api/pictures/search?q&source&page&license&lang`, `POST /api/pictures/fetch {source, id}` (201). Sources (`PICTURE_SOURCES` in validate.js): **Openverse** (`api.openverse.org/v1/images/?q&page&page_size=20&license&mature=false`; `license` `any` = `cc0,pdm,by,by-sa`, `nc` adds `by-nc,by-nc-sa`; no-derivatives are never asked for, since ProQuiz crops and unveils; detail `/v1/images/<uuid>/`, its `url` downloaded first, then `/v1/images/<uuid>/thumb/?full_size=true`; anonymous limits seen on 2026-10-11: 20 a minute, 200 a day, thumbnails 1000 a day; a 400/401 past page 1 means "no more") and **Wikimedia Commons** (`commons.wikimedia.org/w/api.php`, `generator=search`, `gsrsearch=filetype:bitmap|drawing <q>`, `gsrnamespace=6`, `formatversion=2` (pages sorted by `index`), `prop=imageinfo` with `extmetadata` (`Artist` is HTML → `stripHtml()`), `iiextmetadatalanguage` nb/en; fetch by title with `iiurlwidth=1920`, the render downloaded only from `upload.wikimedia.org`/`thumb.wikimedia.org`). The browser never sends an address: `safeUrl()` (https, no IP literals or local names) is checked on every hop (`redirect: 'manual'`, at most 3), `MAX_PICTURE` 15 MB (Content-Length and while streaming), `imageKind()` (`logoKind()` + GIF) must be png/jpg/gif/webp (SVG and anything else → 415 `picture-bad-type`), then `store.addFile('picture.<kind>')`. Every upstream call sends `USER_AGENT`. Searches are cached 10 min (200 entries). Errors: 400 `bad-source`/`bad-query`/`bad-id`, 404 `picture-missing`, 413 `picture-too-big`, 415, 429 `rate-limited` (+ `retryAfter`, also Wikimedia's `ratelimited`/`maxlag` in a 200), 503 `no-internet`, 502 `picture-failed`.

**Credits:** `set.credits = {"<file>": {title, author, license, licenseUrl, source, sourceUrl}}`, tidied by `cleanCredits(credits, usedFiles(set))` in validate.js (only pictures in use, short texts, https links; `clean()` in store.js keeps them, and `filesOf` is `usedFiles`), so exports and imports carry them. The editor (`openPictureDialog({query, onPick})`, the static `#pic-dialog` on top of `#q-dialog`): source pills `picSource` (two lines each) and licence pills `picLicense` (Openverse only; Wikimedia shows `.pic-wiki-note`), both remembered in localStorage (`proquiz.picSource`, `proquiz.picLicense`), the query from the question (answer for the answer picture), Enter searches, `.pic-grid` of `.pic-tile` buttons (thumbnail with `referrerpolicy=no-referrer`, falling back to the original; `.pic-badge`, `.nc` in yellow), **Show more**, a preview (`.pic-preview`, **Back** keeps the results, **Use this picture**), offline (`navigator.onLine` or `no-internet`) and rate messages. `pruneCredits()` runs in `changed()`; `.ed-credit` under a credited picture, and `#ed-credits` (a `<details>`) under the quiz.

**TV:** setting `showCredits` (on, lobby tick in `#group-look`); `creditFor(state, file)` in game.js gives `{author, license, source}` (never the title) in `displayView`'s `q.credit` only at `revealed`, `final.credit` once the answer is shown, and Quick `q.credit` from `result`; never in phone views. `.pic-credit` on the TV, `.host-credit` in the host's picture captions (always). `licenseName()` in i18n.js translates "Public domain". Tests: `test/pictures.test.js`, `test/e2e-pictures.mjs` (screenshots `editor-pic-*.png`, `tv-picture-credit*.png`, `host-picture-credit.png`, `quick-tv-picture-credit.png`; the browser's own outside requests are routed, so nothing goes on the internet).

## Find a song clip

(`songs.js`, the editor's button next to **Choose a file** in the clip field; the fourth internet exception, with the same rules as the picture search: editor only, laptop only, only when the host searches; a found clip is a normal file afterwards). Deezer's public API, no key (checked 2026-10-11): `createSongs({store, fetchImpl, now})` (wired in `startServer({songOptions})`, tests pass a fake `fetchImpl`) has `search({q, page})` → `GET https://api.deezer.com/search?q&limit=10&index` → `{results: [{id, title, artist, album, cover, duration, preview, link}], page, more}` (`more` from Deezer's `next`; `cover` only from `COVER_HOSTS` cdn-images.dzcdn.net / e-cdns-images.dzcdn.net; `preview` is the signed, expiring MP3 address, handed to the editor **only for the ▶ button in the dialog, never stored**) and `fetch({id})` → `GET https://api.deezer.com/track/<id>` again, the `preview` downloaded only from `PREVIEW_HOSTS` cdnt-preview.dzcdn.net (`safeUrl()` on every hop, `redirect: 'manual'`, at most 3; `MAX_SONG` 2 MB by Content-Length and while streaming), `isMp3()` (an ID3 tag or an MPEG frame sync with a valid version and layer; else 415 `song-bad-type`), then `store.addFile('song.mp3', bytes)` → `{name, kind: 'audio', credit: {title, author: <artist>, source: 'deezer', sourceUrl: <link>}}`. Deezer puts its errors in a 200 body: `error.code` 4 (quota) → 429 `rate-limited`, 800 (no data) → 404 `song-missing`; also 400 `bad-query`/`bad-id`, 413 `song-too-big`, 503 `no-internet`, 502 `song-failed`; a 5xx is retried once; searches cached 10 min; every upstream call sends `USER_AGENT`. Routes in `apiHandler` (laptop only, 403 on the tunnel listener, 403 for any `Sec-Fetch-Site` but same-origin/none): `GET /api/songs/search?q&page`, `POST /api/songs/fetch {id}` (201).

**Credits:** `cleanCredits()` accepts clip file names and `SONG_SOURCES` `['deezer']` (no licence fields; `edCredits` is "Picture and song credits"). `creditFor()` gives `{author, license: '', source}` (never the title); `displayView` adds `q.clipCredit` at `revealed`, `final.clipCredit` with the final's answer, Quick `q.clipCredit` from `result`; never in phone views; `.clip-credit` (styled as `.pic-credit`) on the TV says "ABBA · preview from Deezer" (`songCreditLine`, gated by `showCredits` like pictures), the host's clip line always carries it (`.host-credit`). The editor (`openSongDialog({query, onPick})`, the static `#song-dialog` on top of `#q-dialog`, shaped like the picture dialog): the terms note `songIntro` ("30-second previews from Deezer, for private, non-commercial quizzes…"), the query from the answer, Enter searches, `.song-list` of `.song-row` (cover with `referrerpolicy=no-referrer`, title, artist · album, m:ss · "30 s preview", `.song-play` ▶ playing the preview on one shared `Audio` (one at a time, stopped when the dialog closes), `.song-use`), **Show more**, offline (`navigator.onLine` or `no-internet`) and rate messages (`SONG_ERRORS`).

**Use this clip** → `/api/songs/fetch` → `audio` set, `audioStart`/`audioLength` cleared, the credit into `set.credits`, then the trim bar shows the whole preview; `.ed-credit` under the clip says "Song: Dancing Queen – ABBA · Deezer" (`songCreditEditor`, the host-only place the title shows), and `#ed-credits` lists it with a ♪ instead of a thumbnail. Tests: `test/songs.test.js`, `test/e2e-songs.mjs` (screenshots `editor-song-*.png`, `editor-trim-*.png`, `tv-song-credit.png`, `host-song-credit.png`, `quick-tv-song-credit.png`; covers and ▶ previews are routed in the browser, so nothing goes on the internet; it also checks that the TV's trimmed clip pauses by itself, 0 replays it and P after the end starts it over).

## On the website

(`docs/dev/web-plan.md` §4, Phase 4.) The same `pictures.js` and `songs.js` run inside the game room's Durable Object (`web/room.js searchRequest()`), with `store: null`, so `fetch()` gives `{bytes, kind, credit}` instead of writing a file. Routes: `GET /r/<code>/api/pictures/search` and `…/songs/search` (JSON, as on the laptop), `POST …/pictures/fetch` and `…/songs/fetch` (201 with the bytes, `Content-Type`, `x-proquiz-name` = `picture.<kind>` or `song.mp3`, and `x-proquiz-credit` = the credit as URL-encoded JSON; errors as `{error, retryAfter?}` with the laptop's statuses). Only with the host's key in `x-proquiz-key` (this browser's room from `public/js/myroom.js`; the key claims the room like an upload) and only from the editor itself (`Sec-Fetch-Site` same-origin or none, else 403 `forbidden`): the Worker's plain `/api/pictures/*` stays 404. They run in the room, not the stateless Worker, because a picture may be 15 MB and the free plan gives a Worker request 10 ms of CPU but a Durable Object request 30 s. `browserApi` in quizapi.js (`roomCall()`) then puts a picture through `shrinkPicture()` and `store.addFile()` (a clip straight into `addFile`) and returns `{name, kind, credit}` exactly like the laptop, so the editor's dialogs and `onPick` are the same code; a file the website's store still refuses (over 8 MB and not a JPG/PNG to shrink) says `picErrTooBigWeb`. Wikimedia's credit texts follow the editor's language (`lang` in the fetch body). The safety rules are unchanged (`safeUrl()` on every hop, the size caps, the type checks). Tests: `test/web.test.mjs` and `test/e2e-web.mjs` against the pretend internet in `test/fake-upstream.mjs` (the `UPSTREAM` Worker variable, honoured only for a 127.0.0.1/localhost address and never set in wrangler.toml).
