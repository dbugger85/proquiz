# ProQuiz history: what was built, and when

The build log moved out of PLAN.md on 2026-10-11 so that PLAN.md stays short. Every entry is kept as it was written (the owner's decisions are quoted in each). PLAN.md has the decisions table, the status and the open items; CLAUDE.md and docs/dev/ say how things work now.

## Build steps

1. ✅ Basic setup: server, placeholder pages, notes
2. ✅ Game rules (`lib/game.js`) with unit tests
3. ✅ Lobby and joining: phone join page, host lobby with QR code and team list, server wiring, server tests
4. ✅ Board and questions on `/host` and `/display`, keyboard controls
5. ✅ Buzzers end to end: phone button, who was first, correct/wrong/lock-out, timers
6. ✅ Sounds, vibration, keep-awake, reconnecting, autosave and resume
7. ✅ Final round screens (wager, answer, judging)
8. ✅ Question editor with checks, import and export, picture and sound uploads, and choosing a quiz in the lobby
9. ✅ Polish: keyboard help (?), a game-night guide in the README, a Norwegian sample quiz, and tests that both languages have every text
10. ✅ Packaging: `npm run build` makes zips for Windows, Mac (Apple Silicon and Intel) and Linux (x64 and arm64), published as GitHub releases

## Also done
- Picking the tile from the phone (planned with Fable, decided by the user on 2026-10-04): a lobby setting, on by default. The picking team's phone shows the categories, then the points, and the question opens at once. The host can always click a tile too. No time limit. Only the picking team gets the board, with names, points and used tiles only.
- Making a quiz with AI by copy and paste (planned with Fable, decided by the user on 2026-10-04): no API key and no internet in ProQuiz. The editor writes a request from topics, example questions, a difficulty (kids 5–9, easy, medium, hard, expert), the board size, the final and the language. The host pastes it into Claude or ChatGPT and pastes the answer back, and it becomes a new quiz with a note to check the facts. Filling only the empty tiles of an existing quiz isn't built.
- Background music (planned with Fable, 2026-09-27): four built-in generated tunes that follow the game (lobby, calm between questions, thinking that gets intense in the last 3 s, a soft hum while a team answers, silence at reveals and for sound clips and the Kaosmodus reel, suspense in the final, party music after the fanfare), your own file per moment, on/off (B) and a volume slider, separate from the effects.
- Slowly appearing pictures (planned with Fable, 2026-09-27): a per-question option "Show the picture slowly" (seconds until it's clear). It pixelates from big blocks to clear, runs while the buzzers are on, freezes on a buzz, and the buzz timer starts once it's clear. No dropping points, not on the final. (A blur style and the Quick quiz were added on 2026-10-11, see below.)
- Kaosmodus / Crazy mode (planned with Fable, decided by the user on 2026-09-27): an instant bomb, triple, hot seat, rescue (no penalty), turbo (the picking team, 3 random questions, 5 s each, no penalty, no buzzing), jackpot (a secret pot), and freeze, with a mystery-reel reveal on the TV. Off / a little (≈3) / lots (≈6) at random anywhere on the board, and no badge. Placing specials by hand in the editor isn't built.
- Sound clips in questions (asked for by the user), e.g. "Which song is this?". A clip plays on the TV when the question opens, pauses on a buzz, plays on when others may buzz again and at the reveal. The host has P (play/pause) and 0 (from the start). Each clip can have a start time.
- Pictures in questions (asked for by the user): `image` shows with the question, `answerImage` only when the answer is revealed. This works for the final question too, and a picture can replace the question text.
- A modern redesign (2026-09-26, asked for by the user): ink-violet stage, glass tiles, the Unbounded font.

- Daily Double as a Kaosmodus special (decided by the user on 2026-10-05): the picking team bets on its phone (up to its score or the board's top value), answers alone, and a wrong answer loses the whole bet whatever the penalty setting is. No bet means the tile's value. The host can type the bet too.
- The picking phone chooses who to freeze (2026-10-05). The host can still click a team.
- AI fills only the empty spots (2026-10-05, "make it smart to adjust to what's already there"): the request shows the quiz so far, fills empty tiles, missing answers, missing questions for a given answer, category names and the final, matches the existing difficulty, style and language (or a chosen level), takes topics for empty categories, and never changes what is there. Picture and sound questions without text are left alone.
- Placing specials by hand in the editor (2026-10-05): a `special` per question. They always play (a lobby tick turns them off), and Kaosmodus adds random ones on other tiles.
- Fairer buzzing (planned with Fable, asked for by the user on 2026-10-06): a lobby setting, off by default. The server measures each phone's clock and Wi-Fi delay, the phone sends when the button was pressed, and after the first buzz arrives the server waits 0.15 s and gives the question to the earliest press. A phone can't claim more than its own measured delay (at most 0.25 s), and a press from before the buzzers opened counts as too early. The lobby shows each phone's delay in ms.
- Round 2 (planned with Fable, decided by the user on 2026-10-06): an optional second board with its own questions (`round2` in the quiz file), points pre-filled at double in the editor but editable, a lobby tick shown only when the quiz has one. After the first board comes a "Round 2" intro on the TV; the team with the fewest points picks first. Crazy mode re-rolls its specials on the new board (plus hand-placed round 2 specials), and the jackpot pot carries over. The AI can make a round 2 (with its own topics) and fill its gaps. Both sample quizzes have a round 2.
- Quick quiz, a multiple-choice mode (planned with Fable, decided by the user on 2026-10-10): a second kind of quiz file (`kind: "quick"`) in named **sections**, each with a title card and the standings on the TV between them, and a default time per question. Each question has 2 to 4 coloured answer shapes, shown on the TV and as buttons on the phones. The user's decisions:
  - Each phone is a player (up to 30), with its own name; colours may repeat.
  - Faster right answers score more (1000 at once down to 500 at the last moment). Per question in the editor: normal, double or no points. A streak bonus is a lobby setting, off by default.
  - Showing the question and answers on the phones is a lobby setting for everyone, off by default (for players who can't see the TV).
  - The host presses Space between every screen; only the "question first, then the answers" wait is automatic (4 s by default, 0 = wait for Space).
  - After each question: how many picked each answer, the fastest right answer with a fun title, then a top 5 with arrows. Each phone shows its place and the gap to the next player. A podium at the end.
  - The editor has **New quick quiz** with section cards and a multiple-choice question dialog, and the AI dialog can make a quick quiz (sections, questions per section, topics, language). Filling empty spots with AI for a quick quiz came on 2026-10-11 (see below).
  - Two sample quick quizzes (English and Norwegian). The word "Kahoot" is never shown in the game.
- Players elsewhere, joining over the internet (planned with Fable, decided by the user on 2026-10-10, built after the Quick quiz): a Cloudflare quick tunnel (free, no account) started from the lobby's **Players elsewhere** group. ProQuiz finds `cloudflared` or offers a one-time download of the official program into the ProQuiz folder. A second QR code and address (**From anywhere**) show in the host lobby and on the TV. For safety the tunnel gets its own listener where nobody can be the host or use the editor or `/api/`. An optional 4-digit PIN (off by default) for players joining over the internet, shown in the lobby and on the room's TV. Turning it on in a Quick quiz also turns on the question text on the phones (with a note). Board-quiz players elsewhere open the TV page over the internet (`/display`). Fairness: a higher allowance for slow phones (0.6 s instead of 0.25 s), a longer wait for their buzzes, and in a Quick quiz half the measured round trip is taken off the answer time. Showing board questions on the phones was left out.
- How players join (decided by the user on 2026-10-10): instead of an on/off button and two QR codes, a lobby setting **Players join: On this Wi-Fi / Over the internet** (saved like other settings). Over the internet, the lobby and the TV show only the internet code (plus the PIN); while it is being made or isn't working they say so and show the Wi-Fi code for now. A saved "over the internet" starts the tunnel when the host opens the lobby, not when ProQuiz starts. A small warning on the host screen if it stops during a game.
- Several right answers in a Quick quiz (decided by the user on 2026-10-10): a question can mark more than one option right; players still pick one, and any right one counts. Not every option may be right.
- Branding (asked for by the user on 2026-10-10: "upload a custom logo in the upper left corner, and general branding"): in the lobby's **Look and branding** section, a logo (PNG, JPG, SVG or WebP, up to 2 MB, with an optional white backing for dark logos), an optional event name and an accent colour (ProQuiz violet, blue, teal, green, orange, red or your own). The logo replaces the "ProQuiz" name in the corner of the TV (all game long), the laptop, the editor and the phones' join screen, and shows big on the TV's join and end screens with the event name. Kept in the ProQuiz folder for every quiz, never in exports; changed only on the laptop. Team colours stay as they are.
- Calm music after the answer (planned with Fable, decided by the user on 2026-10-10): instead of silence, a soft built-in ambient tune (no drums) fades in about a second after the reveal chime, in both kinds of quiz, and gets a little fuller under the Quick quiz's top 5. It follows the music switch and volume, and the lobby has an own-music slot for it ("After the answer, and the standings"). Questions with a sound clip stay quiet.
- An animated top 5 (planned with Fable, decided by the user on 2026-10-10): it first shows the standings from before the question, then the new points count up with soft ticks, then the rows glide to their new places with a whoosh (someone new rises in from below, someone who drops out slides away), about 2.5 s in all. The phones' own points, the board quiz's score strip, the podium and the board quiz's end list count up too. With the system's "reduce motion" setting it shows the end result at once. No lobby setting.
- Avatars (planned with Fable, decided by the user on 2026-10-10): every phone picks a little cartoon face when it joins, a player's **avatar** in a Quick quiz and the team's **mascot** in a board quiz. A dice button gives a random one (a phone gets one on its first visit and remembers it), and **Customise** opens tabs (skin 6, hair 8, hair colour 6, eyes 5, mouth 5, glasses 4, hats 6) with picture tiles that show the whole face with each option. All drawn by ProQuiz itself, offline. The faces show on the TV lobby, the top 5 (the face takes the place circle's spot, with the place as a small badge), the standings, the podium, the fastest answer, the board quiz's score strip, the buzzer plate, the final and the end list, in the host's lists, and at the top of the phone. Optional in the rules, so old phones and saved games still work (just the name). A TV lobby with many players makes the QR code and the name plates smaller so up to 30 fit.
- Find a free picture (planned with Fable, decided by the user on 2026-10-11): in the editor's question dialog every picture slot has **Find a free picture** next to **Choose a file**. A search window with two sources as pills, **Openverse** (first, photos from Flickr, museums and more) and **Wikimedia Commons** (flags, maps, places, famous people, paintings); the last one used is remembered. The licence is a clear pill choice too, **Free for any use** (the default the first time) or **Also non-commercial** (Openverse only; on Wikimedia a note says everything there is free to use), and the last choice is remembered. Every result and the preview show the licence (non-commercial ones in yellow), with a **Show more** button for the next page. **Use this picture** copies it into the quiz like an upload, so the game itself stays offline; the server does every request (the browser only says "picture X from Openverse"), keeps originals up to 15 MB (Wikimedia's 1920 px render), and refuses SVG files from the internet. Who made it and the licence are saved in the quiz (`credits`, by file name), shown under the picture in the editor and listed under the quiz, and the TV shows a small credit line once the answer is out (lobby setting **Picture credits on the TV**, on by default). No-derivatives pictures are left out (ProQuiz crops pictures and can show them as blocks). The search needs internet; the editor says so plainly when there is none.

- Two more kinds of Quick quiz question (planned with Fable, decided by the user on 2026-10-11): **Tick all that are right** (players tick every right answer and press **Submit answers**; only exactly the right ones score; every answer may be right) and **Put in order** (the answers are written in the right order, the game shuffles them, players tap them in order and submit; only the whole order scores, all or nothing). Both take their speed points from the Submit press. The existing style stays as the normal **Pick one** question (one right answer, or several where any one counts, but not all), with its checkboxes. Question texts never say how many answers are right: the TV and the phones say what kind of question it is. The samples got one of each, the AI request asks for at most 1 in 5 of each, and the editor has a **Kind of question** choice.

- Bigger crowds and reactions (decided by the user on 2026-10-11): **16 team colours** instead of 8 (the 8 new ones clearly different from the old, all readable on the dark TV with dark or white names; a board quiz still takes 8 teams, picking from all 16; each colour has its own buzzer note). A **Quick quiz takes up to 100 players** (was 30): the host lobby's list scrolls, the TV lobby shows the newest 47 plates and "+ n more", the host's side list scrolls, and a note in the lobby says more than 30 hasn't been tried in a real game yet (it depends on the Wi-Fi router). **The TV lobby shows the newest player first** (board and quick), the host keeps the join order. The **top 5 is centred under its title** (an empty column on the right as wide as the arrows' column). **Player reactions** in the Quick quiz: while the result and the top 5 show, the phones have six emoji (😂 🔥 😱 👏 😭 🎉, a fixed list, no free text); a tap floats up on the TV with the player's name and avatar in their colour and fades out in about 3 s, at most 12 on screen, one a second per player, nothing stored in the game. Lobby setting **Players can send reactions**, on by default.

- New version notice (decided by the user on 2026-10-11): when the host page opens the lobby, ProQuiz asks GitHub (at most every 6 hours, never when it starts, never from the TV or the phones) whether a newer release is out. If so, a small friendly banner at the top of the lobby says **ProQuiz 2.3.0 is available** with a short line from the release notes, a **Download** button that opens the release page in a new tab, and "Your quizzes and settings stay where they are." The × closes it for this session. The current version shows in small text under the settings, and the lobby's **Look and branding** group has a tick **Check for new versions when ProQuiz starts** (on by default; off means ProQuiz never asks). Anything going wrong (offline, GitHub busy) shows nothing.

- Update now (planned with Fable, decided by the user on 2026-10-11, built on the new-version notice): in the downloaded program the banner also has **Update now**. ProQuiz asks first ("Update to ProQuiz 2.3.0? … Your quizzes and settings stay where they are. This page connects again by itself."), then downloads the zip for this computer from its own GitHub release page (and nowhere else), checks it against the release's SHA256SUMS.txt, unpacks the program file next to the running one, starts it once with `--version` to be sure it runs, and only then swaps the files (the old program is kept as ProQuiz.old until the next start). Then it saves, lets go of its port and starts the new program in the same window: the black window on Windows, the Terminal window on a Mac and the terminal on Linux stay the window of the running ProQuiz, so closing it still stops ProQuiz, and the host page connects again by itself and says "ProQuiz was updated to 2.3.0". The banner shows "Downloading… 42%", "Checking the download…" and "Restarting ProQuiz…". Anything going wrong (a failed download, a file that doesn't check out, a new program that won't start) leaves everything as it was and says so in plain words, with the Download link as the way out; if the new program dies right after the restart, the old one is put back and started again with that message. Only from the lobby, only on the laptop, never under `npm start` (there the banner keeps just Download). Tried for real on Linux with two compiled programs on 2026-10-11; Windows and Mac are for the owner to try (unsigned programs: the firewall may ask again).

- Louder by default, archive, description and cover, a future-proof export (asked for by the user on 2026-10-11): the music and the sound effects both start at 80 % (the effects got their own slider in the lobby's Sound group; a saved music volume still at the old 35 moves to 80 once). Quizzes can be **archived** in the editor's list (personal to this computer, kept in `archived.json`, the samples too): they leave the lobby's list and sit in a folded "Archived" section with **Bring back**. Every quiz can have a **description** (up to 300 letters) and a **cover picture** (uploaded or found with the free picture search, credit included), shown in the editor's list, at the top of the quiz and under the quiz picker in the lobby; they are part of the quiz file, so exports carry them. The `.proquiz.json` export is now versioned (`proquiz`, `app`, `exported`; see docs/file-format.md): a file from a newer ProQuiz is refused with a plain message, an older one goes through upgrade steps (none needed yet), and **Export all quizzes** writes every quiz the host made (archived ones too, samples left out) into one file that Import reads back, saying how many it got. Not shown on the TV (its lobby has no quiz title) or the phones.

- Quit ProQuiz (asked for by the user on 2026-10-11: closing the browser didn't stop the program): a quiet **Quit ProQuiz** button at the very bottom of the lobby's settings, under the version line (during a game: **Main menu** first, so it can't be hit by accident). ProQuiz asks first ("Quit ProQuiz? The game is saved, and you can continue it next time. Players' phones and the TV screen lose the connection."), then saves the game, says goodbye to every screen and ends the program. The host page says "ProQuiz has stopped. You can close this tab. To play again, start ProQuiz again."; the TV and the phones say "The game has ended. The host closed ProQuiz." and stop trying to reconnect. Only from the laptop, never over the internet tunnel. The START HERE notes and the README name the button as the way to stop (closing the window still works too).

## Song clips and quiz languages (planned with Fable 2026-10-11, owner said "build both") — built 2026-10-11

**Status:** A, B and C were all built on 2026-10-11 (not yet committed or released).

**Spotify: decided against.** Spotify's Developer Policy (since May 2025) says "Do not create a game, including trivia quizzes". Development-mode apps are capped at 5 users and need Premium (Feb 2026), the 30 s previews are gone, and audio can't be cached, so it would also need internet during the game. Apple MusicKit and YouTube embeds were ruled out too.

### A. Trim every sound clip (offline) — built 2026-10-11
- New optional field `audioLength` (seconds, 0.5–600) next to `audioStart`, on board tiles, the final and Quick questions. It's an optional field, so the format version stays 1.
- **Owner's addition:** the editor shows a **trim bar** under the clip (the whole clip as a track with a handle at each end: drag the left one for the start, the right one for the end), replacing the plain "Start at" field. A **Try it** button plays the trimmed part, and the times are shown as m:ss. Leaving the right handle at the very end means "to the end" (no `audioLength`).
- `clipFor()`/`quickClip()` pass `{file, start, length}`; `clip.js` pauses at `start + length`; key 0 replays the trimmed part. The host's line says "(from 1:05, 10 s)".

### B. Find a song clip (Deezer 30 s previews, editor only) — built 2026-10-11
- New `songs.js`, modelled on `pictures.js`: `GET /api/songs/search?q&page` (api.deezer.com/search, no key) and `POST /api/songs/fetch {id}` (re-fetch the track, download its `preview` only from `cdnt-preview.dzcdn.net`, max 2 MB, must really be MP3, then `store.addFile`). It uses the same guards, errors and cache as pictures. The preview URL is signed and expires, so it is never stored.
- The editor's clip field gets a **Find a song clip** button, which opens a dialog. The search starts from the answer. Each result shows its cover, title, artist and a ▶ play button, and **Use this clip** fills in the clip, after which the trim bar from A trims the 30 s. A note says "30-second previews from Deezer, for private, non-commercial quizzes".
- The credit goes in `set.credits` (source `deezer`). The TV shows "Artist · preview from Deezer" only after the answer, through the existing `showCredits` setting. It is never shown on phones, and the title is never shown before the reveal.

### C. Extra languages in a quiz — built 2026-10-11
Built as planned, with the owner's additions (flags, the host switch) and these details: the phone's own buttons follow the choice only when it is English or Norwegian *and* not the quiz's main language (so players who don't pick anything see no change); the host's grey lines show the languages the teams in the game have actually picked; the flag of a language spoken in many countries is one sensible choice (English → Great Britain, Arabic → the Arab League, Persian → Iran, Urdu → Pakistan, Tigrinya → Eritrea, Chinese → China, Hindi → India); the font stacks name system fonts with Thai, Arabic, Devanagari, Ethiopic and CJK letters so nothing shows as boxes. Tests: `test/languages.test.js`, the language parts of the game, Quick, server, export and AI tests, and the browser tests (`phone-lang-*.png`, `host-lang-*.png`, `editor-languages*.png`).
- Translations are stored on the item they translate: `translations: {"<code>": {...}}` on the quiz (title, description), categories/sections (name), questions (question, answer, Quick `options` by index), and the final. `set.lang` is the main language and `set.languages` the added ones. No format version bump; old files are unchanged.
- New `lib/languages.js`: a fixed list of about 25 languages with their own names (**must include Thai, `th`, "ไทย", owner's request; make sure Thai text renders on phones and the TV, since the bundled fonts have no Thai letters, so fall back to the system font for it**) and **a small flag each (owner's addition)**. Flags are small bundled SVGs, not emoji, because Windows browsers don't draw flag emoji. Helpers: `textOf` (per-field fallback to the main text), `optionsOf`, `translationItems` (stable ids like `q0-1`, `o0-1-2`), `missingTranslations`, `cleanTranslations`.
- **Owner's addition: a host switch.** A lobby setting `quizLanguages` (on by default; the tick is shown only when the quiz has extra languages). When it is off, phones get no language choice and everyone plays in the main language.
- **Phones:** "Read questions in:" pills with flags on the join form. The default is the phone's browser language if the quiz has it, else the main language. The choice is remembered, and a globe/flag pill in the header changes it later (message `language {lang}`). In the board quiz, a phone that picked another language shows the question (when the TV shows it) and the answer (at reveal); main-language phones stay pure buzzers. In Quick quiz, a translated player always sees the question and options. The phone's own buttons follow the choice only for en/no. Text uses `dir="auto"`.
- **TV:** always the main language. **Host:** small grey translation lines under the question and answer, and a flag badge per team. The host judges final answers as now.
- **Editor:** a Languages block under the description (main language select, chips with a flag and ×, Add a language), a Translations table per language (main text left, translation right, "Show only missing", n missing counts), and **Translate with AI** (copy-paste like Fill empty spots, matched by id, fills only empty slots).
- The sample quizzes get a translation each (sample/quick-sample → Norwegian, eksempel/lynquiz → English).
- Risks to test: translated Quick options must follow `cleanQuick()`'s `keep` remap, the editor's `moveUp()`, and the "put in order" shuffle. The phones-never-see-questions rule is relaxed only via one `wantsText()` function.

## Slowly appearing pictures in the Quick quiz, and a blur style — built 2026-10-11
Asked for by the owner on 2026-10-11 ("The picture reveal was not available in Quick quiz. Add this functionality there as well (both unblur and pixelated)"; not yet committed or released). Every question picture that appears slowly (board tiles and now Quick questions) can do it in one of two ways, chosen with **Pixels** / **Blur** pills under **Show the picture slowly** in the editor: Pixels is what it did before (big blocks that get smaller) and stays the default; Blur starts as a heavy blur that sharpens smoothly. In a Quick quiz the picture stays hidden while the question is read, starts appearing when the answers open and is clear when the time to answer is up (a longer time is cut to the question's seconds, and the editor says so), and the result shows the clear picture next to the bars. The points are as before (faster is better, so a brave early guess pays). The host sees "Picture: n% clear" in a Quick quiz too, and phones never get the picture. The sample Quick quizzes' flag question now appears as a 12-second blur. The file format gains the optional `unveilStyle` (version stays 1).

## Fill empty spots with AI for Quick quizzes — built 2026-10-11
Asked for by the owner on 2026-10-11 (not yet committed or released). The editor's **Fill empty spots with AI** button now shows under a Quick quiz's sections too. It finds empty questions, questions with fewer than four options (true-or-false questions with their two are left as they are), questions with no right answer marked and nameless sections, and a number **Fill each section up to this many questions** (starting at the most any section has, at least 5, at most 30) makes the AI add new questions at the end of the shorter sections. Copy and paste like before; the request shows the quiz so far with "" for the gaps and the same rules as a new quick quiz (4 options or 2 for true or false, the answer copied from the options, at most 1 in 5 tick-all or put-in-order, never saying how many are right), matching the quiz's language and difficulty (or a chosen level), with topics for completely empty sections. Pasting back fills only the gaps (options only into empty places, the right answer only when none was marked, the kind never), adds the new questions, and marks every filled or added row with a dashed edge and the "check every answer" note. Picture and sound questions without text are left alone. Also on the same day: in **Make questions with AI** the number of categories or sections now sits above the topics, and the topics hint says how many to write.

## Owner feedback fixes after the first real game — built 2026-10-11
The owner played the first real Quick quiz with a group (six teams, a 75" TV) on 2026-10-11 and reported three things (fixed the same day, not yet committed or released):
- **The top 5 on the TV was far too narrow:** the plates were thin pills about a quarter of the screen wide, names were cut to one letter ("L", "Ol…") and the arrows were squeezed to the left, while most of the screen was empty. The TV's browser didn't work out the list's width the way the laptop's does, so the top 5 now has a plain width of about 60 % of the screen for the plates (no clever CSS), centred under the title with the arrows outside, and a long name (more than 14 letters) is set a little smaller instead of being cut, so every name up to the 20-letter limit shows in full. The same care went into the standings between sections and the podium (a two-line winner's name no longer pushes the steps' points off the bottom). Tested with long Norwegian names on a 1080p and a 720p TV, glass look on and off.
- **No top 5 after the last question:** the result of the very last question now goes straight to the podium when the host presses Space (the button says **Show the podium**). Undo from the podium goes back to that result.
- **AI-made quick quizzes lost their question kinds:** ChatGPT left the kind out of every question, so "Hvilke av disse …" questions came in as pick-one with several right answers and "Sorter disse …" as pick-one. The request now asks for a kind on every question (pick one, tick all, put in order, or pick one where any of several counts), ProQuiz guesses the kind from the wording when the AI still leaves it out, and the note above the new (or filled) quiz says what it read, for example "Read 19 questions: 14 pick one, 3 tick all that are right, 2 put in order", and points out any question that sounds like tick-all or put-in-order but came in as pick one.

## The website version — built 2026-10-15 and 2026-10-16
Planned with Fable on 2026-10-15 (the owner accepted every recommended default; `docs/dev/web-plan.md` is the decision record, `docs/dev/web.md` how it works) and built in seven phases over the two days, not yet committed, released or deployed. ProQuiz now also runs as a website on Cloudflare (Workers + Durable Objects, free plan) from the same code: the host opens the site, the browser makes a secret key and a six-letter room code from it, and each room is one Durable Object holding the same game code as the laptop (the hub, moved out of `server.js` into `lib/hub.js` so both can run it) in memory, with nothing stored and no accounts. Phones and the TV join with the code or the QR. The host's quizzes, pictures, clips, logo and colours live in the host's browser (IndexedDB, the same `.proquiz.json` export and import as the laptop, with a backup reminder after 30 days and a Safari note); the quiz goes to the room over the socket, its pictures and clips are uploaded into the room before a game (8 MB a file, 48 MB a quiz, big photos shrunk to 1920 px), the editor's picture and song search run in the room, and the room sends the game back to the host's browser after every change, so a restart of the website (every deploy restarts every room) ends in "Continue the last game?" with the phones put back in their teams. A forgotten room closes after 30 minutes; the PIN protects a room whose code got around; the TV page never shows it. The laptop version is unchanged in behaviour (every laptop suite green after every phase, the editor's screenshots identical).

The ship review (2026-10-16) fixed, before any deploy: the wrong-key limiter could lock the host's own key out, so any player with the code could keep the host out of its room (now only other keys are refused, the right one always works); a same-key race between the host page and the editor on a fresh room; the chosen quiz and the lobby's settings being lost after a restart of the website (any save goes back now, as the laptop reads its file); and two free-plan savers (the keep-alive ping every 30 s instead of 10 s, since every answer is a counted message, and an empty room with nobody connected closing after 5 minutes instead of 30).
