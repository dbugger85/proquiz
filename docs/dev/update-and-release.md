# Updates, packaging and releases

The new-version notice (`lib/update.js`), **Update now** (`lib/selfupdate.js`, compiled program only), packaging (`scripts/build.mjs`) and how a release is made.

## New version notice

(`lib/update.js`, another exception to "never load anything from the internet"; only the server, only for the host laptop): the server knows its version from `package.json` (`readVersion()` in server.js, read with `new URL('./package.json', ROOT)`; `scripts/build.mjs` packs it in with `--include package.json`; null if unreadable → no version line, no check), sent as `info.version` in the host's `welcome` (the lobby's `#about-line`, "ProQuiz 2.2.1", under the settings). `createUpdateCheck({version, fetchImpl, now})` (wired in `startServer({updateOptions})`, tests pass a fake `fetchImpl`): `check()` asks `https://api.github.com/repos/dbugger85/proquiz/releases/latest` with a `User-Agent`, a 5 s timeout and no retries, at most once per `CHECK_EVERY_MS` (6 hours, a failed check too; a check on its way is shared), and `readRelease()` keeps it only when it is not a draft or pre-release, `tag_name` parses as `major.minor.patch` (`parseVersion`, "v2.3.0" → "2.3.0", compared numerically with `compareVersions`), it is newer than the running one, and `html_url` starts with `https://github.com/dbugger85/proquiz/releases/`; `excerpt(body)` turns the release notes into one plain-text line (the first paragraph without headings, markdown or links, ≤ 300 letters). Anything else (offline, 403/429, odd JSON) is silently nothing. `checkUpdate()` in `createHub` runs on a **host hello** (never at server start, never for TVs or phones) when the setting `updateCheck` (default on, lobby tick in `#group-look`, saved with the settings) is on, and broadcasts if the answer changed; `broadcast()` puts `update: {version, url, notes}` in the state messages of host connections only (`!c.remote`, so never over the tunnel's listener; TVs and phones never see it). Host lobby: `#update` (`renderUpdate()` in host.js) at the top of the lobby with `#update-title`, `#update-notes`, the "Your quizzes and settings stay where they are" line, `#update-link` (**Download**, `target=_blank rel=noopener`, only an address on the releases page, else `/releases/latest`) and `#update-close` (×, remembered per version in `sessionStorage` `proquiz.updateSeen`, so it stays closed through later state messages until the tab is closed). `#look-status` says "no version check" when the setting is off. Tests: `test/update.test.js` (the pure parts and the real server with a fake GitHub: newer, same, older, malformed, wrong address, errors, timeout, the 6-hour cache, the setting off, only the host, not over the tunnel) and the banner in `test/e2e-brand.mjs` (screenshot `host-update-banner.png`).

## Self-update, "Update now"

(`lib/selfupdate.js`, another exception to "never load anything from the internet"; **only in the compiled program**, never under `npm start`): `isCompiled()` = `Deno` exists and `process.execPath` isn't the `deno` command (a `deno compile`d program reports its own path, checked 2026-10-11). `createSelfUpdate({version, exe, system, compiled, fetchImpl, spawnImpl, relaunchImpl, check, base, hosts, args, env, beforeRestart, exit, onStatus, log, initialError})` (wired in `startServer({selfUpdateOptions})`; tests pass fakes) has `available()`, `status()` = `{stage: idle|downloading|checking|restarting|failed, progress, error}` and `run(release, {port})`. The host sends `updateNow`; `updateNow()` in `createHub` takes it only from a host connection (laptop only, never the tunnel's listener), only in the lobby, only with a known newer release and one at a time (`GameError` `update-not-here`/`update-in-game`/`update-none`/`update-busy`), and the state's `update` carries `canInstall` + `install` (the status); every change goes to host connections only as a small `{type: 'update', update}` message (`sendUpdate()`), not a broadcast.

**Download:** `assetUrl()` = `https://github.com/dbugger85/proquiz/releases/download/v<v>/ProQuiz-<v>-<system>.zip` (`systemFor(platform, arch)`: windows, mac-apple-silicon, mac-intel, linux-x64, linux-arm64, the names from scripts/build.mjs), `download()` follows redirects by hand (`redirect: 'manual'`, at most `MAX_HOPS` 4, every hop `allowedUrl()`: https and a host in `ALLOWED_HOSTS` (github.com, objects.githubusercontent.com, release-assets.githubusercontent.com); http only for 127.0.0.1/localhost and only when a test put it in `hosts`), `MAX_ZIP` 200 MB (Content-Length and while streaming), `IDLE_MS` 30 s without data and `TOTAL_MS` 10 min, progress per whole percent.

**Integrity:** `SHA256SUMS.txt` from the same release (`parseSums()`, sha256sum's format; scripts/build.mjs writes it into dist/ from every zip there) must have a matching line (`verifySum()`), else `checksum` and nothing is touched; a release without it can't be installed.

**Unzip:** a pure-JS reader (`readZip()`, `unzipEntry()`: central directory → local headers, stored or deflate through `node:zlib` `inflateRawSync`, CRC32 checked, zip64/encryption refused, `safeZipName()` refuses `..`, `\`, absolute paths and drive letters), and `pickFromZip()` takes out only the program file (exactly one `ProQuiz`/`ProQuiz.exe`, at the top or one folder down, ≥ 1 MB) and the START HERE note.

**Swap** (`installProgram()`): write `ProQuiz.new` (`ProQuiz.new.exe`, `programNames()`), chmod 755, run it with `--version` (`checkVersion()`, 20 s; `server.js` prints the version and ends when started with `--version`) and require the release's version in its output, then `rm .old`, `rename exe → .old`, `rename .new → exe` (a failed second rename is renamed back; errors `start` = nothing changed, `swap`).

**Restart** (`relaunch()`): `beforeRestart` (the server's `prepareExit`: `hub.saveForExit()` writes the game waiting to be continued, or the lobby, to the autosave, then `close()` lets go of both listeners and the sockets) and then the new program is spawned **as a child with `stdio: 'inherit'`, not detached** (same folder and arguments, env plus `PORT=<the port it was on>` and `PROQUIZ_UPDATED_FROM=<old version>`; an earlier restart's `PROQUIZ_UPDATED_FROM`/`PROQUIZ_UPDATE_ERROR` are stripped): the old process stays only as a waiter and exits with the child's code, so the console/Terminal window still belongs to a running ProQuiz and closing it or Ctrl+C stops everything, exactly as the START HERE notes say. The host page reconnects by itself (net.js), and the new program doesn't open a browser when `PROQUIZ_UPDATED_FROM` is set and it got the `PORT` it was given; the host's `welcome.info.updatedFrom` makes the banner say "ProQuiz was updated to …". A child that ends with an error within `EARLY_EXIT_MS` 15 s is rolled back (`rollbackProgram()`: exe → `.failed`, `.old` → exe) and the old program is started the same way with `PROQUIZ_UPDATE_ERROR=restart`, which the new server turns into `initialError` so the banner shows `updateErr-restart`. On every compiled start that isn't an update's own restart (no `PROQUIZ_UPDATED_FROM`/`PROQUIZ_UPDATE_ERROR`), `cleanupOld()` deletes leftover `.old`/`.new`/`.failed` (ignored when busy); the restart keeps `.old` so the rollback can use it.

**Test-only overrides** in server.js (`testUpdateOverrides()`): with `PROQUIZ_TEST_UPDATE=1`, `PROQUIZ_UPDATE_API` and `PROQUIZ_UPDATE_BASE` point the check and the download at a pretend release on 127.0.0.1; without the flag both are ignored.

**Host page:** `#update-now` (shown when `update.canInstall`; the Download link loses `btn-primary` then), `ask()` with `updateAskTitle`/`updateAskText`, `#update-status` (`updateDownloading {pct}`, `updateChecking`, `updateRestarting`, `updateErr-<error>` in red; `.update-banner.busy` spins the icon, hides ×, Download and the notes). Windows/Mac: a file written by the program itself has no Mark-of-the-Web/quarantine flag, so no SmartScreen/Gatekeeper prompt is expected, but the firewall may ask again (the notes say Allow). Tests: `test/selfupdate.test.js` (names, allowlist and redirects, size cap and timeouts, sums, the zip reader against the `zip` command and hand-made bad zips, swap/rollback in a temp folder with shell-script programs and the real `--version` spawn, relaunch with a fake spawn, the whole run, and the real server: refused under Node, outside the lobby, with no release, never from the TV or over the tunnel) and `test/e2e-brand.mjs` (screenshots `host-update-ask.png`, `host-update-progress.png`, `host-update-restarting.png`). The real Linux swap + restart with two compiled binaries was done by hand on 2026-10-11 (see history.md); Windows and Mac need the owner's try.

## Packaging

the Linux build is tested here. Windows and Mac builds can't be run on this laptop, so ask the user to try them. The programs are unsigned: Windows shows SmartScreen ("More info → Run anyway"), and Mac needs right-click → Open. Both ask to allow network access.

## How to release

Only when the owner asks. Bump with `npm version X.Y.Z --no-git-tag-version`, commit, push, `npm run build`, then `gh release create vX.Y.Z dist/* --title "ProQuiz X.Y.Z" --notes-file <notes> --latest`. Upload **everything in dist/**, including `SHA256SUMS.txt`, or Update now refuses the release. Start the notes with one friendly summary sentence: the lobby's update banner shows the first paragraph. Never put a claude.ai session link in a commit, PR or release.

**Then the website** (web.md): `npm run web:deploy` (builds `dist/web` and runs `wrangler deploy`; `npx wrangler login` once per machine). The website serves the same pages and rules as the release, so it is deployed after every release that touches them (the room's `welcome.info.version` comes from `package.json` at deploy time). **Never deploy while a game is on:** a deploy restarts every room, the pages reconnect and the host has to press Continue. The website has no "Update now": the next page load is the new version.
