# Network: protocol, fair buzzing, players over the internet

The WebSocket protocol, which roles may connect from where, fair buzzing (`fairBuzz`), the Cloudflare tunnel (`lib/tunnel.js`) with its own listener and PIN, and keep-awake.

## Protocol

client → `hello {role, teamId?}`. Phones then send `join {name, color, avatar?, lang?, teamId?, pin?}`, `language {lang}` (the quiz language it reads in, see languages.md), `buzz`, `pick {c, i}` (only the picking team), `freezePick {target}` and `bet {amount}` (Kaosmodus, only the picking team), `wager {amount}`, `finalAnswer {text}` and, in a Quick quiz, `answer {option | options | order, at}` (by the question's kind; the server forwards all three and the rules check the shape) and `react {emoji}` (an index into `REACTIONS`; not a game action, see Player reactions in quick-quiz.md). The host sends `cmd {action}` (allowed list: `HOST_ACTIONS` in server.js). The host can also send `resume`, `discardSave`, `mainMenu`, `quit` (stops the program, see Quit ProQuiz in board-game.md), `testSound`, `chooseSet {id}`, `tunnel {on}` (same as choosing `joinMode`, or try again) and `tunnelDownload`. A phone's `buzz` in the lobby just plays its tone. The server → `welcome` (with `info.phoneUrl` and `info.tvUrl`, the TV page's Wi-Fi address shown in the host lobby, for host/display, `teamId` for phones), `joined {teamId}`, `error {code}`, `sound {name, teamId?}` (sounds outside the game, sent to the TV or else the host), `reaction {emoji, name, color, avatar?}` (a player's reaction, same targets as `sound`), and `state {view, connected, displays, tvs, serverNow, resume?, latency?, remote?, needPin?, update?}` after every change (`update` for the host only, see New version notice in update-and-release.md; `welcome.info.version` is the running version), and `bye` to everyone when the host quits ProQuiz (net.js then never reconnects). Error codes are translated as `err-<code>` in i18n.

## Host is laptop-only

the server accepts `role: 'host'` only from loopback addresses (and never on the tunnel's listener, see How players join below), because the host view contains the answers. The TV (`/display`) and phones can connect from anywhere. So the TV page can run on an iPad, another computer or a smart TV's browser (an Apple TV has none, so an iPhone/iPad/Mac mirrors it with AirPlay); the server prints that address and the lobby shows it (`tvElsewhereHint`).

## Fair buzzing

(setting `fairBuzz`, off by default): every phone answers the server's `clock {id}` with `clock {id, t: performance.now()}` (net.js does this before `onMessage`) and sends `buzz {at}` with its press time (the touch event's `timeStamp`). The server (`ping()`, `clockSample()`, `bestSample()`, `pressTime()` in `createHub`) measures each phone 5 times on hello or `resync` (sent when the page becomes visible), once every 5 s and once on `arm`, keeps samples for 20 s, and uses the one with the shortest round trip: `offset = t − (sent + rtt/2)`. A buzz gets `at` (server time) and `slack` (rtt + 5, at most `MAX_SLACK_MS` 250, or `MAX_REMOTE_SLACK_MS` 600 for a phone over the internet: `slackCap(c)`) from the server only, never from the phone; game.js caps it at the larger one. In game.js the press counts as `min(now, max(now − slack, at, q.armedAt))`, a press more than `slack` before `q.armedAt` is `early`, and the first arrival sets `q.decideAt = now + wait` instead of winning, where `wait` (from the server's `buzzWait()`: the largest rtt + 5 of the other measured phones) is clamped to `BUZZ_WINDOW_MS` (150) … `MAX_REMOTE_SLACK_MS`, so a slow phone elsewhere still gets its earlier press counted; `timeout` at `decideAt` runs `decideBuzz()` (earliest press wins, `buzzes` sorted). If every team that may buzz has buzzed it decides at once. `nextTimerAt(state)` is what the server schedules (the window, else `deadline`). Unmeasured phones count by arrival. The host gets `latency {teamId: ms}` in state messages and `latency` messages (shown in the lobby team list). `test/fairbuzz.test.js` uses pretend phones with wrong clocks and lag.

## How players join / players elsewhere

(`lib/tunnel.js`, lobby group `#group-remote`): the setting `joinMode` (`'wifi'`, the default, or `'internet'`; `JOIN_MODES` in game.js) is a pill choice like the other settings and is saved with them.

**The server keeps the tunnel in line with it** (`syncTunnel()` in `createHub`): choosing internet starts the tunnel and choosing Wi-Fi stops it (checked in `dispatch()` whenever `joinMode` changes), and a host hello in the lobby starts it when the setting says internet and the tunnel is `off`. So a saved 'internet' never starts a tunnel when ProQuiz starts, only when the host page opens the lobby, and a failed one isn't retried by itself. `resume()` keeps the lobby's `joinMode` and `remotePin` (they belong to the session, not the saved game). The tunnel itself is a Cloudflare quick tunnel (`cloudflared tunnel --no-autoupdate --url http://127.0.0.1:<port>`, no account) gives a random `https://<words>.trycloudflare.com`.

**Security:** cloudflared connects locally, so everything it passes on comes from 127.0.0.1; it is therefore pointed at a **second listener** (`openRemote()` in `startServer()`, 127.0.0.1 on a free port, opened when the tunnel starts and closed when it stops) where every connection is remote: `serveFile(…, {remote: true})` refuses `/api/`, `/host` and `/editor` (403), and `hub.connect(ws, req, {remote: true})` sets `c.remote` and `c.local = false` (no host hello). No headers are trusted. `createTunnel()` finds cloudflared (`candidates()`: PATH plus the usual install folders, next to the program, `<data dir>/bin/`), spawns it, reads the address with `parseTunnelUrl()` (ignores `api.trycloudflare.com`), and after "Registered tunnel connection" waits until the name resolves through DNS-over-HTTPS (`dnsReady()`, so no resolver caches "not found" from asking too early) and the address answers (`reachable()`), at most 30 s, before saying `on`. Status `{status: off|starting|on|missing|downloading|failed, url, reason: start|timeout|download|stopped, progress}`. `download()` fetches the official asset (`assetFor(platform, arch)`, `RELEASES` = GitHub latest download; Mac `.tgz` unpacked with `tar`) into `<data dir>/bin/` and starts. `stop()` is off at once (SIGTERM, SIGKILL after 3 s, since cloudflared waits for open connections); `process.on('exit'/signals)` kills it. Host messages `tunnel {on}` (sets `joinMode`; `on` while it already says internet tries again, the **Try again** buttons) and `tunnelDownload`. State messages carry `remote` (host: the status plus `remoteTeams`; TV: `{status, url}`, the url only when on) and, for a remote phone not in a team while a PIN is set, `needPin`.

**PIN:** setting `remotePin` ('' or 4 digits, made by the host page's `newPin()`), checked in `checkPin()` for remote joins without a team (`bad-pin`; at most 10 wrong PINs a minute for all remote phones together, then `pin-wait`); never in `phoneView`, and blanked in the view of a TV page opened over the tunnel. Remote TV pages don't count in `displays`/`tvs` (so single-screen mode and the laptop's sounds stay) but still get `sound` messages. In a Quick quiz, the host page turns `quickPhoneText` on once per tunnel session when it is on (`remoteQuickDone`, with `#remote-note`).

**Screens:** the host lobby and the TV show **one** QR code (`#qr`): the Wi-Fi address, or with `joinMode` internet the internet address (host: label `#join-label`, the PIN `#remote-pin`, the `/display` link `#remote-tv`; TV: `#qr-label`, the PIN `#remote-pin`). While the internet address isn't ready (starting, missing, failed) the host's join card shows `#join-wait` (status text, **Try again** / download) above a smaller Wi-Fi code labelled "On this Wi-Fi, for now" (`.join-card.waiting`), and the TV `#tv-wait` with the Wi-Fi code (`#qrs.waiting`). Long addresses wrap before a dot (`urlNodes()` in ui.js). During a game the host page shows `#remote-warn` (`renderRemoteWarn()`) when joining over the internet stopped, is starting again, or came back on a new address, with **Try again**. `startServer({tunnelOptions})` passes test doubles (`ready`). Tests: `test/remote.test.js` (listener refusals, PIN, pretend cloudflared shell scripts, download with a fake fetch) and `test/e2e-remote.mjs`.
